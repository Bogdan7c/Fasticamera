# Профили устройств

Каталог `device-profiles/<производитель-модель>/` хранит данные, снятые с конкретного устройства и нужные продукту.
Каждый файл самоописывающий (поле `schema`) и содержит блок `provenance` (откуда числа). Только JSON/Markdown: бинарники и сырые снимки сюда не кладём.

## `oneplus-cph2447/lens-shading.json`

Собственная калибровка затенения объектива (сессия 14f), схема `fasticamera.lens-shading-calibration/1`.
Генерирует `tools/device-probe/pc/shading_calibrate.py` (команда — в `tools/device-probe/README.md` и в `provenance.tool`).

```
schema   "fasticamera.lens-shading-calibration/1"
device   { manufacturer, model }
cameras[] (порядок: "2" основная, "3" ширик, "1" фронтальная)
  camera_id      id Camera2
  active_array   { width, height } — активный массив в пикселях (для этих режимов равен буферу)
  grid           { columns, rows, points }
  provenance     информационный блок (стенд, число укладок, подгонка, проверки); читатель игнорирует неизвестные поля ТОЛЬКО здесь
```

Конвенция сетки: точка (c, r), c in [0, columns), r in [0, rows), лежит в пикселе активного массива
`((W-1)/(columns-1)*c, (H-1)/(rows-1)*r)`; точки идут построчно (row-major). В точке 4 числа `[R, G_even, G_odd, B]`
(G_even — зелёный в чётных строках активного массива). Это множители усиления на «сырой» RAW после вычитания чёрного:
все >= 1, наименее затенённая точка канала даёт 1. Значения округлены до 6 знаков.

Без экстраполяции: узлы во внешних 16 px кадра берут значение модели в ближайшей измеренной точке (центр крайнего блока замера) отдельно по каждой оси; полином на последних 16 px ненадёжен (угловой gain между степенями 12 и 16 расходился на ~17 %). Тем же зажимом считается максимум модели для нормировки gain.
