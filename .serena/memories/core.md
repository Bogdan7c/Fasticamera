# Fasticamera — core (точка входа)

Короткая карта текущего состояния (граф ссылок, не журнал).

## Проект
- Личная камера для OnePlus 11 (CPH2447, salami), Rust + Vulkan (ash), в магазин не публикуется. Приватный репозиторий GitHub `Bogdan7c/Fasticamera`, ветка `main`. Пакет `dev.fasticamera` (debug: `dev.fasticamera.debug`).
- Цель: сырой поток с сенсора без копий в Vulkan, вся обработка своя, снаружи — клон камеры iOS 26 (Liquid Glass). Конечная цель владельца — паритет с iPhone по видео (решение 16), затем фото «как iPhone» (17); костяк обязан выполнять задел V1–V10.
- Действующий план — `user/foundation/` (README: решения 1–91, архитектура, владельцы состояния, инварианты, V1–V10, порядок сессий 00–17, общие правила, бэклог). Отчёты — `user/foundation/results/NN.md`. Межплановый бэклог — `user/general_problems/general_backlog.md` (п. 1: OxygenOS 60 Гц до первого касания; п. 2: уничтожение instance после импорта AHB убивает поток под validation; п. 3: плавающий ПК-стенд задержки `latency_profiles_bench`, решение 60).
- Сделано: 00 (GO), 01 (скелет, CI), 02 (шов Android ↔ Rust), 03 (Vulkan-ядро, поток рендера, импорт AHB, sync_fd, тестовая картинка на телефоне), 04 (камерный бэкенд Camera2 NDK, движок камеры, 60 к/с через NDK подтверждены), 05 (RAW в Vulkan без копий: лизинг, паспорт кадра, отладочная мозаика на экране; 5 мин 4:3@60 RAW10 без сбросов и CPU-копий). 06 (эталон ISP на CPU `isp-model`, цвет по DNG-матрицам, демозаик Menon 2007, тон с сохранением оттенка; сверка с colour-hdri/colour-demosaicing/LibRaw). 07 (ISP видоискателя на GPU; приёмка на телефоне — подсессия 07a, `results/07.md`): живой видоискатель из RAW через слитый compute-проход, ISP = к/с сенсора, каждый кадр ровно один раз; таблица «стадия → мс GPU → мА» (весь ISP ≈ 119 мА, из них статистика AWB ≈ 55 мА); до 08 видоискатель зелёный (HAL не считает баланс в RAW-only сессии, решение 55). 08 (3A; приёмка на телефоне — подсессия 08b, `results/08.md`, закрыта 18.11)\1Пустой поток стоит +12,5 мс задержки и ≈ +105 мА (решения 70–71); регионы AF работают; AWB на белом листе ΔE ≈ 1,3–1,4. 08a (код, 18.11; наш AE вместо вендорского, `results/08a.md`; приёмка на телефоне и срез тока пустого потока — подсессия 08c). 08c закрыта 19.11 (части 1–2): наш AE во всех запросах продукта (`aeMode OFF`), видоискатель не хуже вендорского (лист: среднее по кадру −0,12 EV, вендорский +0,83), перелёт подтяжки на ступеньке света исправлен (`AppliedExposure.reach`, 0,5 → 0,03 EV), ток наш = вендорский (554/560 мА), ключи статистики ток не срезают (владелец: не занимаемся), регрессия зелёная; открыто — виньетирование на потоке приложения (углы −1…−1,7 EV, бэклог README). `3a` повторён после правок (debug+release зелёные). ## Ловушки окружения
- Буфер logcat `main` 256 КиБ: читать потоком с `-T <секунды.миллисекунды>` (целые секунды ловили строку прошлого прогона), падения — `logcat -b crash -d`. `logcat -c`/`-G` не трогать.
- Телефон — личный: запускать только свои APK, скриншоты без нужды не снимать.
- Запуск Activity — интентом лаунчера (`-a MAIN -c LAUNCHER`).
- `adb shell pm revoke/grant` — только с опцией разработчика (решение 30).
- `scripts/device-smoke.sh --no-build` ставит последний собранный APK.
- **Наше приложение видно поверх экрана блокировки** (`setShowWhenLocked`): экран кажется разблокированным, а `dumpsys trust` → `deviceLocked=1`. Системная камера (и любые чужие окна) поверх блокировки не открываются — `camera-evict` драйвер теперь проверяет это сам. Просить владельца разблокировать по-настоящему (PIN/отпечаток).
- Экран: `KEYCODE_SLEEP` игнорируется; `KEYCODE_POWER` переключает (жать только при `mWakefulness=Awake`). После циклов экрана телефон на блокировке: системный диалог разрешения не виден, `permission` требует разблокировки владельцем.
- Фоновый процесс Oplus замораживает (`do_freezer_trap` в wchan) — не путать с зависанием, если приложение ушло с переднего плана.
- Стеки без root: `simpleperf record --app <пакет> -g` (debuggable); `debuggerd` требует root.
