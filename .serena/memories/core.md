# Fasticamera — core (точка входа)

Короткая карта текущего состояния (граф ссылок, не журнал).

## Проект
- Личная камера для OnePlus 11 (CPH2447, salami), Rust + Vulkan (ash), в магазин не публикуется. Приватный репозиторий GitHub `Bogdan7c/Fasticamera`, ветка `main`. Пакет `dev.fasticamera` (debug: `dev.fasticamera.debug`).
- Цель: сырой поток с сенсора без копий в Vulkan, вся обработка своя, снаружи — клон камеры iOS 26 (Liquid Glass). Конечная цель владельца — паритет с iPhone по видео (решение 16), затем фото «как iPhone» (17); костяк обязан выполнять задел V1–V10.
- Действующий план — `user/foundation/` (README: решения 1–91, архитектура, владельцы состояния, инварианты, V1–V10, порядок сессий 00–17, общие правила, бэклог). Отчёты — `user/foundation/results/NN.md`. Межплановый бэклог — `user/general_problems/general_backlog.md` (п. 1: OxygenOS 60 Гц до первого касания; п. 2: уничтожение instance после импорта AHB убивает поток под validation; п. 3: плавающий ПК-стенд задержки `latency_profiles_bench`, решение 60).
- Сделано: 00 (GO), 01 (скелет, CI), 02 (шов Android ↔ Rust), 03 (Vulkan-ядро, поток рендера, импорт AHB, sync_fd, тестовая картинка на телефоне), 04 (камерный бэкенд Camera2 NDK, движок камеры, 60 к/с через NDK подтверждены), 05 (RAW в Vulkan без копий: лизинг, паспорт кадра, отладочная мозаика на экране; 5 мин 4:3@60 RAW10 без сбросов и CPU-копий). 06 (эталон ISP на CPU `isp-model`, цвет по DNG-матрицам, демозаик Menon 2007, тон с сохранением оттенка; сверка с colour-hdri/colour-demosaicing/LibRaw). 07 (ISP видоискателя на GPU; приёмка на телефоне — подсессия 07a, `results/07.md`): живой видоискатель из RAW через слитый compute-проход, ISP = к/с сенсора, каждый кадр ровно один раз; таблица «стадия → мс GPU → мА» (весь ISP ≈ 119 мА, из них статистика AWB ≈ 55 мА); до 08 видоискатель зелёный (HAL не считает баланс в RAW-only сессии, решение 55). 08 (3A; приёмка на телефоне — подсессия 08b, `results/08.md`, закрыта 18.11)\1Пустой поток стоит +12,5 мс задержки и ≈ +105 мА (решения 70–71); регионы AF работают; AWB на белом листе ΔE ≈ 1,3–1,4. 08a (код, 18.11; наш AE вместо вендорского, `results/08a.md`; приёмка на телефоне и срез тока пустого потока — подсессия 08c). 08c закрыта 19.11 (части 1–2): наш AE во всех запросах продукта (`aeMode OFF`), видоискатель не хуже вендорского (лист: среднее по кадру −0,12 EV, вендорский +0,83), перелёт подтяжки на ступеньке света исправлен (`AppliedExposure.reach`, 0,5 → 0,03 EV), ток наш = вендорский (554/560 мА), ключи статистики ток не срезают (владелец: не занимаемся), регрессия зелёная; открыто — виньетирование на потоке приложения (углы −1…−1,7 EV, бэклог README). `3a` повторён после правок (debug+release зелёные). Решение 78: полуавтомат «дотягивать ли недобор выдержки» — переключатель в сессии 16 (по умолчанию дотягивать; «как снято» в коде нет). 08a закрыта. 09 (19.11, без кода): спецификация экрана камеры в `docs/ios-camera/` — эталон iOS 27 на iPhone 17 Pro Max (решение 79), раскладка в pt + правило 1 pt = 1080/440 px с лишней высотой в верхнюю полосу (82), поведение/пороги жестов, пружины и прокрутка, Liquid Glass (у Apple чисел нет — стартовые `GlassStyle` из реверса Kyant), хаптика, ассеты (Inter + свои иконки на Phosphor/Lucide, 81), утверждённый `scope-v1.md` (вспышка вкл/выкл в v1, карусель — только реализованные режимы, 80), `feature-map.md` — задел под будущие функции, механизмы М1–М6 (83); `components.md` — без дублирования: новый crate `ui-kit` между `ui-core` и `camera-screen` (элементы K1–K10: кнопка, шкала с упорами для зума/EV/ручных, карусель, выбор, панель-морф, плашка, рамка фокуса, затвор; модели значений; токены — числа только в токенах), создаётся в 10 (84). Метки происхождения чисел `[doc]/[measured]/[review]/[reverse]/[derived]/[estimate]`: оценки в коде — параметры «подгонка, не Apple». 10 (19.11, `results/10.md`): crate-ы `ui-core` (механика UI) и `ui-kit` (элементы K3–K6, модели значений, токены), только ПК — в APK войдут с экраном 12. Бэклог: задержка «палец → экран» (предсказание касаний, 120 Гц на жест). 11 (19.11, код на ПК, `results/11.md`; решения 86–88): `ui-draw` («что рисовать», нейтральный) + `ui-render-vulkan` (GPU) + растровый набор `gpu-vulkan`; стекло поверх живого видоискателя — проход UI после композитора, ПО УМОЛЧАНИЮ ВЫКЛЮЧЕН (ставит только сценарий `glass`, конец сценария снимает); RADV ≈ 1,2 мс на кадр со стеклом; паника источника UI ловится в месте вызова (источник снимается), сценарий `glass` меряет после прогрева (`glass_warmup` → `glass_live`). 11a закрыта 19.11 (раздел «Проверено на телефоне (11a)» в `results/11.md`): стекло на живом видоискателе OnePlus 11 зелёное в debug (5 из 6; первый прогон дня — 8 переполнений буфера, причина не установлена, бэклог 16a) и release, владелец принял вид, блик от наклона и golden-кадры; GPU UI p95 ≈ 5,6–6,1 мс (DVFS) при пороге 0,5 периода (решение 90); «пропуск кадра» = выпал/повтор, «позже задуманного vsync» — только цифра `late_frames` (решение 91); ток стекла — в 16a (решение 89). Найдена и исправлена гонка `render-loop`: квитанция освобождения surface теперь после публикации статуса. 12 (20.11, код на ПК, `results/12.md`; решения 92–94): экран камеры iOS — новый crate `camera-screen` поверх живого видоискателя ПОСТОЯННО (по умолчанию `camera_screen.enabled = true`); телефонная приёмка — подсессия 12b (решения 92, 96). Следующая — 12a (эталон по скринам iPhone), потом 12b.
- Факты о телефоне: `mem:device/oneplus11-camera-facts`.

## Ловушки окружения
- Буфер logcat `main` 256 КиБ: читать потоком с `-T <секунды.миллисекунды>` (целые секунды ловили строку прошлого прогона), падения — `logcat -b crash -d`. `logcat -c`/`-G` не трогать.
- Телефон — личный: запускать только свои APK, скриншоты без нужды не снимать.
- Запуск Activity — интентом лаунчера (`-a MAIN -c LAUNCHER`).
- `adb shell pm revoke/grant` — только с опцией разработчика (решение 30).
- `scripts/device-smoke.sh --no-build` ставит последний собранный APK.
- **Наше приложение видно поверх экрана блокировки** (`setShowWhenLocked`): экран кажется разблокированным, а `dumpsys trust` → `deviceLocked=1`. Системная камера (и любые чужие окна) поверх блокировки не открываются — `camera-evict` драйвер теперь проверяет это сам. Просить владельца разблокировать по-настоящему (PIN/отпечаток).
- Экран: `KEYCODE_SLEEP` игнорируется; `KEYCODE_POWER` переключает (жать только при `mWakefulness=Awake`). После циклов экрана телефон на блокировке: системный диалог разрешения не виден, `permission` требует разблокировки владельцем.
- Фоновый процесс Oplus замораживает (`do_freezer_trap` в wchan) — не путать с зависанием, если приложение ушло с переднего плана.
- Стеки без root: `simpleperf record --app <пакет> -g` (debuggable); `debuggerd` требует root.
