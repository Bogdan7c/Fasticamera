# Команды

Оболочка владельца — fish (`$PIPESTATUS`, heredoc-ы bash в ней не работают; скрипты запускать как файлы).

- Все проверки без телефона: `scripts/ci-checks.sh all` (стадии: fmt, clippy-host, clippy-android, test, scripts-test, boundaries, module-size, apk; можно перечислить отдельные стадии).
- Rust на ПК: `cargo test --workspace` и `cargo test --workspace --all-features` (фича `debug-scenarios` включает отладочные сценарии).
- Тесты скриптов: `python3 -m unittest discover -s scripts/tests -t scripts/tests`.
- Guardrail границ: `python3 scripts/check-crate-boundaries.py [--offline] [--manifest-path X]`; правила — `scripts/crate-boundaries.toml`.
- Ratchet размера: `python3 scripts/module-size-check.py [--update-baseline | --adopt PATH]`; политика и baseline — `scripts/module-size-policy.toml` (`[baseline]` всегда последняя секция).
- APK: `cd android && ./gradlew assembleDebug assembleRelease` (нужны `ANDROID_HOME`, `JAVA_HOME`; скрипты выставляют дефолты сами через `scripts/lib/common.sh`).
- Телефон:
  - `scripts/device-deploy.sh [--variant debug|release] [--no-build] [--log-seconds N]` — сборка, установка, запуск, logcat тега `Fasticamera`.
  - `scripts/device-smoke.sh [--variant ...] [--no-build] [--timeout S] <сценарий>` (`--no-build` ставит последний собранный APK). Сценарии: `hello`, `panic` (только debug), `lifecycle` (скрипт сам жмёт HOME и возвращает), `permission` (`--timeout 60`; сбрасывает и возвращает разрешение камеры только нашего пакета, сам жмёт «Don't allow»; экран разблокирован, телефон не трогать; нужна опция разработчика OxygenOS), `motion` (гироскоп ≥ 380 Гц; ориентация `unknown`, если телефон лежит), `platform` (тепло, 120 Гц, проигрывает 9 вибраций, показывает и снимает тестовую подсказку на экране — гонять первым перед сценариями с владельцем) — коды выхода: 0 прошёл, 1 упал, 2 нет устройства, 3 нет строки результата, 4 сборка/установка/запуск, 64 неверный вызов.
  - Сценарии сессии 03: `render` (`--timeout 120`; ритм 10 с, период ≈ 16,67 мс при цели 60 Гц), `render-lifecycle` (`--timeout 400`; 20× HOME + 3× экран кнопкой питания; в конце телефон на блокировке), `ahb-import`, `gpu-fence` (`--timeout 60`). Ритм сравнивать на release (`--variant release`), validation — на debug.
  - Validation layer для debug APK: `scripts/fetch-validation-layer.sh` (кэш `~/.cache/fasticamera/vulkan-validation-layers/<ver>/`, офлайн при кэше; вызывается из `apk`-стадии CI и `build_apk debug`).
  - Сырые времена показа: запуск с `-e log_filter "info,fasticamera::gpu::display_timing=trace"`; шаги создания GPU-контекста — `fasticamera::gpu::init=debug`.
  - Переопределить фильтр логов на один запуск: `adb shell am start -S -n dev.fasticamera.debug/dev.fasticamera.MainActivity -e log_filter "info,fasticamera::scenario=trace"`.
  - Сценарии сессии 04 (нужно выданное разрешение камеры и разблокированный экран): `camera-catalog` (`--timeout 30`; после результата скрипт сверяет каталог с `dumpsys media.camera`), `camera-stream` (`--timeout 120`; 6 шагов из `camera.scenarios.stream_steps`: 60 к/с основной 16:9/4:3, ширик 4:3@60, фронт, логическая 0, RAW16), `camera-evict` (только debug, `--timeout 90`; драйвер запускает системную камеру `am start -a android.media.action.STILL_IMAGE_CAMERA` — решение 38). Подробности отчёта — `grep FASTICAMERA_DETAIL`.
  - Сценарии сессии 05 (разрешение камеры, экран разблокирован): `raw-stream` (`--timeout 120`, 60 с), `raw-stream-endurance` (`--timeout 420`, 5 мин — критерий выхода 05), `raw-stream-cpu-probe` (только debug, `--timeout 60`; проходит, только если счётчик копий вырос). `--artifacts-dir DIR` — куда класть скриншоты `screencap` (вне репозитория; по умолчанию `mktemp -d`); пороги — `scripts/smoke_screen.toml`. Задержка и «возраст кадра» — в отчёте `raw-stream` (`latency`, `arrival_age`). Release-пакет `dev.fasticamera` — отдельное приложение: разрешение камеры выдать `adb shell pm grant dev.fasticamera android.permission.CAMERA`. `camera-stream` проверяет и жизнь reader-ов (`readers` retired/deleted/leaked).
  - Сценарии сессии 07 (release для замеров, только батарея для тока; разрешение камеры, экран разблокирован): `viewfinder` (`--timeout 120`; минута ISP: к/с, «ровно один раз», мс GPU, AWB, задержка, скриншоты; `--neutral-card` — серая карта в центре вышла серой, осмысленно после AWB 08), `viewfinder-latency` (`--timeout 240`; ABBA профилей baseline/tuned), `viewfinder-stage-budget` (≈ 6 мин на строку по 60 с, по умолчанию 9 строк — `--timeout 3600`; `--stages awb_statistics,whole_viewfinder` — подмножество; `--ab-window-ms 15000` — короткие окна, только мс GPU, `--timeout 1200`), `viewfinder-endurance` (`--timeout 720`, 10 минут), `video-headroom-bench` (`--timeout 720`, стенд V4, 120 Гц, скрипт касается экрана). Сравнение «до/после» со старой сборкой: `git worktree add --detach <scratchpad>/baseline <sha>`, сборка там (`ANDROID_HOME`/`JAVA_HOME` выставить вручную — вне скриптов они не заданы), запуск `<worktree>/scripts/device-smoke.sh --no-build`.
  - Сценарий сессии 08: `3a` (`--timeout 150`; ungated; шаги: живой 3A + пустой поток, AWB готов, тапы центр + 4 угла, ручная 1/1000 ISO 400 и 1/10 с → «ограничено», EV 0/±1, блокировка AE/AF, серия 2/4/8/16 мс; `--neutral-card` — серая карта на стадии `awb_ready`; регионы фокуса осмысленны со сценой «близко сбоку, далеко в центре»; с 08c блокировка ведётся подсказками на экране: отсчёт 3 с, «ЗАКРОЙ ОБЪЕКТИВ РУКОЙ» 5 с, «УБЕРИ РУКУ» — владелец закрывает объектив рукой, иначе заметка «СТАТИЧНАЯ сцена»).
  - 08c: `ae-trace` (`--timeout 160`; наш AE, фото 36 с + видео 36 с, каждые 6 с отсчёт 3-2-1 и «ЩЁЛКНИ ЛАМПОЙ» на экране — владелец щёлкает лампой, затем 20 с статики; без ступенек — провал). `--endurance-ms MS` — длина `viewfinder-endurance` на запуск (180000 — короткий A/B тока перезапусками; ток пишет только endurance, а не `viewfinder`). Зонд: `tools/device-probe/pc/probe.py` (запускать из `tools/device-probe`). `--exposure-controller own|vendor` — выбор AE на запуск для любого сценария (A/B). `--neutral-card` меряет уровень центра против среднего серого 0,20 в EV (допуск 0,2) — карта должна заполнять ВЕСЬ кадр, иначе мерится сцена, а не карта (ошибка части 1). Сверка запроса продукта без зонда: `adb shell dumpsys media.camera` → «Last request sent». Ток — только телефон без кабеля (`dumpsys battery` → `AC powered: false`).
  - Зонд 3A (Java, отдельно от продукта): `cd tools/device-probe && python3 pc/probe.py run control threea [yuv=640x480 companion_targeted=0] [only=<фазы>] [camera= width= height= ae_fps= req_keys=-]`; фазы — в `camera/threea/ThreeAPhases.kt`; результаты в `~/fasticamera-captures/probe-runs/<дата>/`.
  - ПК-стенд задержки (подставная камера, без телефона): `cargo test -p render-loop --release --test latency_profiles_bench -- --nocapture` (~70 с).
  - Зонд 00 для сверки с Java: `cd tools/device-probe && python3 pc/probe.py run control stream camera=0 size=4096x3072 format=0x25 ae_fps=30 frames=150` (flavor `control` = `dev.fasticamera.probe`).
- Устройство выбирается по модели `CPH2447`; несколько — задать `ANDROID_SERIAL`.

## UI-рендер и стекло (сессия 11)
- Сценарий 11/11a: `scripts/device-smoke.sh [--variant release] --timeout 90 glass` (видоискатель + демо-стекло 30 с; скриншоты на стадии `glass_live`; бюджет p95 GPU UI = период × `camera.scenarios.glass.ui_gpu_budget_fraction`, по умолчанию 0,5 — ловушка грубых ошибок, решение 90; рывки судит проверка видоискателя, `late_frames` — только цифра, решение 91; экран во время прогона не трогать — касание включает 120 Гц).
- Golden: `cargo test -p ui-render-vulkan --test golden`; перегенерация `FASTICAMERA_UPDATE_GOLDEN=1 …`; PNG для глаз `FASTICAMERA_GOLDEN_PREVIEW_DIR=<вне репо> …` (README в `test-assets/ui-render-vulkan/golden/`).
- Замер GPU на RADV: тест бенча в `crates/ui-render-vulkan/tests/` с `--nocapture` (пирамида и проход UI отдельно).
- Запекание шрифта/иконок — автоматически в `build.rs` `ui-draw` (манифест `crates/ui-draw/assets/bake.json`, ≈ 1–2 с).

## Экран камеры (сессия 12)
- Сценарий zoom (13, приёмка 13a): `scripts/device-smoke.sh [--variant release] --timeout 240 zoom` — 19 шагов, сам вводит действия экрана (тапы `.6 / 1 / 2 / 1 / .6`, переворот туда-обратно, тап `1`, проводка колеса настоящими касаниями; с 13b — бесшовные колесо и щипок: туда / обратно до отметки / колебание у 1,0 `hover` / отпускание) и судит: смена объектива дошла (`LensSwitched`), первый живой кадр новой камеры, 0 чёрных кадров при смене, 60/30 к/с, зеркало фронта, вибрации колеса ≥ 30 мс; телефон не трогать. Пороги — `camera.scenarios.zoom`.
- Зонд двух камер (13, план 13b): `cd tools/device-probe; export ANDROID_HOME=$HOME/Android/Sdk JAVA_HOME=/usr/lib/jvm/java-21-openjdk FASTICAMERA_PROBE_OUT=$HOME/fasticamera-captures/probe-runs/13-dual/product; python3 pc/probe.py install control; python3 pc/probe.py run control dual mode=product seconds=30 --timeout 120` (режимы `concurrent`, `preopen`, `product`, `product_standby reps=5`, `product_abba order=ABBAABBA seconds=20 [current=average] --timeout 400` — только на батарее).
- Экран стоит поверх видоискателя ВСЕГДА (`camera_screen.enabled = true`); сценарии smoke снимают его на своё время.
- Сценарий screen (приёмка 12b): `scripts/device-smoke.sh [--variant release] --timeout 180 screen` — 18 шагов: драйвер сам тапает/свайпает/жмёт `KEYCODE_VOLUME_UP` по стадиям `screen_gesture` (жест — в самой стадии); телефон не трогать. Точки — `camera.scenarios.screen` (доли экрана, `[derived]` из раскладки).
- С 12b (решение 105) переполнения джиттер-буфера в `screen` — только цифра `viewfinder.jitter_overflow` (под касаниями поток рендера не успевает за такт, чинится в 16a); провалом остаются в `viewfinder`/`glass`. GPU UI p95 на нагретом телефоне ≈ 8 мс при пороге 8,33 — близко к ловушке.
- Тон видоискателя на один запуск без пересборки (12b): `adb shell am start -S -a android.intent.action.MAIN -c android.intent.category.LAUNCHER -n dev.fasticamera/dev.fasticamera.MainActivity -e tone_contrast 1.5 -e tone_display_middle_gray 0.22`; неверное значение — отказ initialize с полем `viewfinder.tone` в logcat (`native initialize failed`).
- Датчики приложения на телефоне: `adb shell dumpsys sensorservice | grep "pid= *<pid> "` — гравитация и акселерометр должны регистрироваться в момент старта.
- Шум логов: тихий запуск `-e log_filter "info,fasticamera::render::auto_exposure=warn,fasticamera::render::white_balance=warn"`.
- Golden экрана: `cargo test -p fasticamera-app --all-features --test camera_screen_golden` (10 состояний, эталоны `test-assets/camera-screen/golden/`, хранение 6× уменьшено); перегенерация `FASTICAMERA_UPDATE_GOLDEN=1`, PNG полного кадра — `FASTICAMERA_GOLDEN_PREVIEW_DIR=<вне репо>`.
- Логика экрана без GPU: `cargo test -p camera-screen`.

## Эталоны ISP (сессия 06, только ПК)
- Venv вне системы: `uv venv ~/.cache/fasticamera/isp-reference-venv && uv pip install --python ~/.cache/fasticamera/isp-reference-venv/bin/python rawpy numpy scipy pillow colour-science colour-hdri colour-demosaicing`. Запуск скриптов — всегда `.../isp-reference-venv/bin/python -I`.
- Фикстуры `test-assets/isp-model/` (README там): `tools/isp-reference/make_demosaic_fixtures.py`; реальные кропы — `make_real_crops.py --capture-dir ~/fasticamera-captures/c7-reference/captures/204802-f42af9 --stem 2_lamp --out-dir test-assets/isp-model [--full-frame-dir <вне репо>]` (детерминирован: побайтно тот же вывод).
- Посмотреть картинку эталоном: `cargo run -p isp-model --release --example render_capture -- <каталог> full-main-lamp out.ppm [--demosaic preview|quality] [--gamut srgb|display-p3] [--scene-middle-gray X] [--contrast X]` (~4 с на 12 Мп).
- Тесты эталона: `cargo test -p isp-model` (интеграционные: `demosaic_parity`, `demosaic_quality`, `pipeline_end_to_end`, `real_crops`).
