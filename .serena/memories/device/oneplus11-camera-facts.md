# OnePlus 11 (CPH2447) — факты камеры и GPU (сессия 00, 2026-10-25)

Источник истины с доказательствами: `user/foundation/results/00.md`. Зонд для перепроверки после обновлений прошивки: `tools/device-probe` (README там же).

## Система
- OxygenOS 16.0.5.1301(EX01), Android 16 / SDK 36, загрузчик заблокирован, HAL Qualcomm CamX/CHI, `ro.hardware.camera=oemlayer`.
- Logcat main-буфер 256 КиБ — CamX вытесняет записи за секунды; данные зонда идут JSONL-файлом через `run-as`.
- Фоновый процесс Oplus замораживает (`isFrozen`) — Activity с камерой должна быть на переднем плане (`setShowWhenLocked`/`setTurnScreenOn` при запуске с ПК).

## Камеры и доступ
- Видны 0–3 (0 логическая 2+3, 1 фронт S5K3P9, 2 основная IMX890, 3 ширик IMX581). 4 (телевик) и 5 закрыты фреймворком: `SYSTEM_CAMERA` = `signature|privileged|role`; без root недоступны. Имя пакета на это не влияет.
- `com.oneplus.camera` ставится, но ничего не меняет; `com.oppo.camera` — `INSTALL_FAILED_SHARED_USER_INCOMPATIBLE: oplus named app is not match signature`. Решение владельца 20: имя `dev.fasticamera`.
- Публичный RAW: основная 4096×3072 (RAW16/RAW10/RAW_PRIVATE), ширик 4000×3000, фронт 2304×1728/1296; min frame 33 мс (объявлено 30 к/с). Max-resolution карты нет.

## 60 к/с RAW (без root)
- Основная 16:9@60: `CONTROL_AE_TARGET_FPS_RANGE=[60,60]` → режим сенсора 4 (4096×2304@60); буфер 4096×3072, данные в строках 0–2303, ниже нули (центральная вырезка 4:3). 5 мин = 18 000 кадров, 5 пропусков.
- Основная 4:3@60: CamX `org.quic.camera.manualExposure.disableFPSLimits` (byte, 0x804a0000)=1 + `overrideSensorFrameDuration` (int64, 0x804a0001)=16666667, без AE fps range (иначе режим 4); работает и с вендорским AE; `SENSOR_FRAME_DURATION` в результате ложный (33,3 мс) — темп только по SENSOR_TIMESTAMP.
- Ширик 4:3@60: AE `[60,60]` → режим 2 (4000×3000@60). Ключи CamX на ширике ломают поток (0 кадров, похоже перезапуск HAL).
- Вендорские режимы сессии (0x8021 и т.д.) для 60 к/с не нужны; constrained high-speed с RAW отвергнут; 50 Мп публично недоступен.
- Индекс режима сенсора в результате: `org.codeaurora.qcamera3.sensor_meta_data.current_mode` (int32).

## Camera2 NDK (сессия 04)
- 60 к/с через NDK подтверждены: основная 16:9@60 (AE [60,60] в параметрах сессии и запросе) 58,6 к/с в комнате (AE растягивает кадр до 17 мс), 4:3@60 (CamX-ключи только в запросе) 59,8 к/с, ширик 4:3@60 58,9, RAW16 16:9@60 58,4; фронт 30,0.
- Вендорские теги ищутся по имени `ACameraMetadata_getTagFromName` (API 35): disableFPSLimits 0x804a0000, overrideSensorFrameDuration 0x804a0001, is_qcfa_sensor 0x80330000 (на всех камерах). `ACameraManager_getTagFromName` в публичном NDK закрыт (`__ANDROID_VNDK__`).
- Углы обзора по длинной стороне: основная 72,5°, фронт 71,0°, ширик 102,0° (порог роли ширика 90°).
- **Логическая камера 0 не отдаёт финальных результатов запросов**: только частичные (`onCaptureProgressed`), `onCaptureCompleted` = 0; RAW-кадры идут ~30 к/с. Java-зонд даёт то же (`res_fps null`) — поведение HAL, не NDK. Важно для сессии 13 (переключение через логическую камеру).
- RAW-размеры в карте HAL шире, чем знала 00: логическая 0 ещё `raw10 4000×3000`, фронт ещё 2304×1296.

## Поток в Vulkan (сессия 05)
- RAW10 4:3@60 CamX через лизинг: 5 мин = 18 111 кадров, 60,04 к/с, пул 6 (на руках максимум 4), 0 исчерпаний; результат запроса приходит почти всегда раньше буфера (ожидание пары ~0).
- Возраст кадра при приходе в наш reader (начало экспозиции → колбэк): ~30 мс (27–43). Задержка до экрана: p50 67 мс debug / 83 мс release (наша часть — очередь показа и фаза тика vsync, вход для 07).

- Первые кадры после старта потока почти чёрные (AE не сошлась); через ~1,5 с нормальные.
- ~3 % кадров видоискатель вытесняет (камера 60,04 и экран 60,00 расходятся по фазе).

## Видоискатель с ISP (сессия 07, 27.10.2026)
- В сессии из одного RAW-потока (наш режим, 4:3@60 RAW10) HAL отдаёт `SENSOR_NEUTRAL_COLOR_POINT` как `0/0` во всех трёх каналах — весь поток. Временная нейтраль до нашего AWB берётся из `COLOR_CORRECTION_GAINS` того же кадра (`render-loop` `isp_params::NeutralSource`).
- `BatteryManager.CURRENT_NOW` на OxygenOS 16 — в **мА**, а не в мкА, как в документации Android (≈ 490 при камере; `dumpsys battery`, блок Oplus «Battery current : 509» — те же мА). Конфиг `camera.scenarios.power.current_now_unit = milliamps`; проверка правдоподобия ловит неверную единицу. `CHARGE_COUNTER` — мкА·ч (≈ 1 952 000 при 57 %).
- Swapchain на SurfaceView даёт `DISPLAY_P3_NONLINEAR_EXT` + 10 бит (с `VK_EXT_swapchain_colorspace`); выбран P3.
- Время GPU прохода ISP (timestamp-запросы) ~9 мс debug / ~12 мс release, но отладочная мозаика 05 стоит те же ~13 мс: время «растягивается» до бюджета кадра — почти наверняка DVFS Adreno (частоту снять нельзя: perfetto `power/gpu_frequency` пуст, `/sys/class/devfreq` закрыт). Мс GPU на этом телефоне — не мера стоимости работы; мера — ток (мА) и вычитание A/B.
- Цена ISP (A/B тока, окна 60 с, 07a): весь видоискатель +119 ± 11 мА к камере без ISP (358 мА), из них статистика AWB ≈ 55 ± 12 мА; остальные стадии ≤ ~15 мА (часто «не различим»). Мс GPU стадий после `subgroupAdd` неотличимы от нуля (DVFS).
- 07a (буфер на 1 кадр): release ISP 59,88 к/с при сенсоре 60,03, вытеснений 0, 100 % кадров ровно один раз; задержка p50 77–81 мс (профиль «как было» — 69 мс: сход на ближнюю линию не срабатывает из-за DVFS-растянутого времени GPU, решение 57). ADPF время GPU не меняет.
- В RAW-only сессии `COLOR_CORRECTION_GAINS` = `[1,1,1,1]` (не только нейтральная точка `0/0`): баланса HAL нет, видоискатель зелёный до AWB 08. AWB HAL внутри считает (провайдер пишет `vendor.oplus.camera.awb.pregain`, ~3700 K), но в результат не отдаёт.
- Logcat: буфер `main` на этой прошивке ≈ 8–9 с (SystemUI ~90 КБ/с); записи нашего процесса во всплеске теряются молча (`__android_log_write` отвечает успехом) — решение 58.

## 3A (зонд `threea`, сессия 08, 18.11.2026, камера 2 RAW10 4:3@60 CamX)
- **В сессии из одного RAW-потока 3A Qualcomm мёртв целиком**: `AF_STATE` нет, `LENS_FOCUS_DISTANCE` залип, `AE_STATE` вечно SEARCHING (AE разомкнут, наследует яркость), баланс `[1,1,1,1]`. Любой второй обработанный выход в сессии оживляет всё; достаточно YUV 640×480, **объявленного, но не цели запросов** (0 кадров в нём): AF/AE/AWB живы, 60,04 к/с, RAW не теряется. Проверено также 176×144/320×240 (цель) и PRIVATE 640×480. На других камерах/режимах и «RAW тот же» — не проверено (раунд 4 сорвал обрыв adb).
- AF: холодный лок по триггеру 27–34 кадра (≈ 0,5 с), тёплый ~8; `ACTIVE_SCAN` уже в кадре триггера; CANCEL → INACTIVE, объектив стоит. Регионы AF/AE с YUV в результате выглядели подменёнными на дефолтный центр (1434,1076,1228,920) — не проверено на сцене «близко/далеко».
- Работает при `AE_MODE_OFF` (ручной сенсор): AF живой, баланс HAL живой; смена экспозиции AF не сбрасывает в INACTIVE.
- Ручная выдержка квантуется по строке: 1 мс → 0,996 мс, 8 → 7,996, 2 → 1,992; видна через 7–8 кадров после смены повторяющегося запроса (первый результат с новым тегом уже несёт её). ISO 400 → 400/401.
- Компенсация −18…18 по 1/6 EV; +12 шагов → ×4,007 экспозиции. `maxRegions` AE 1 / AWB 0 / AF 1; AF-режимы 0–4 (фронт — только 0); блокировки AE/AWB есть; антибандинг 0–3, в результате AUTO. `aeAvailablePriorityModes` = [0] (публичного полуавтомата нет); вендорские `org.codeaurora.qcamera3.iso_exp_priority.*` в тёмной сцене не применились и **липкие**.
- Серия через `captureBurst` поверх повторяющегося: кадры подряд, порядок сохранён, экспозиции квантованы, RAW на все; на стыке пачки теряется один такт (22,7/24,7 мс).
- Детектор мерцания `android.statistics.sceneFlicker` **фальшивый** (08c, 19.11): `60HZ` на 99,9 % кадров — при дневном свете, под аккумуляторным LED (мерцания нет), при `AE_MODE_OFF` и при вендорском AE; вендорский тег `AntiBandingMode` всегда 120 — эхо настройки «сеть 60 Гц». Вендорский AE под LED берёт 16,66 мс (2×8,33). Решение 77: автодетекта нет.
- 08c: `org.quic.camera2.statsconfigs.{AEC,AWB}StatsControl` (байт) = 0/1/2 видимо ничего не меняют (60 к/с, AF сходится, экспозиция та же); ток не измерен (телефон был на зарядке). В секции есть ещё `AFDStatsControl` (AFD — детектор мерцания), `AECFrameControl`, `DigitalGainControl`, `AWBWarmstartGain` и др. (0x80130000…).
- 08c: `dumpsys media.camera` показывает «Last request sent» и «Latest received frame» клиента с ключами (`aeMode` и т.д.) — независимая сверка запроса продукта без зонда.
- 08c: наш AE (камера 2, 4:3@60): EV ±1 → ×1,89…2,06 / ×0,46…0,52; произведение замирает через 30–31 кадр после команды блокировки; первая попытка шага 4 негодна: лист занимал ~1/7 кадра (центр +0,79 EV, сцена с тенями); на той же сцене наш AE на 0,42 EV темнее вендорского. Переснять лист на весь кадр (часть 2).
- **08b (18.11):** пустой поток оживляет 3A на всех рабочих камерах (основная 16:9@60 и 4:3@60, ширик 4:3@60, фронт 30), 60 к/с, без потерь; минутный прогон чистый. **Без 3A объектив не двигается вовсе** — даже `AF_MODE_OFF` + `LENS_FOCUS_DISTANCE` (HAL только эхом возвращает число, `LENS_STATE` нет); с пустым потоком ручной фокус работает. RAW с пустым потоком тот же (режим сенсора 1, чёрный 64, средние совпадают при одинаковой резкости в пределах разброса фокуса ±0,7 DN). Логическая 0: в Java-зонде HAL-провайдер падал (SIGABRT в `CamX::ImageBuffer::BindImportedBuffer`, сам поднимается за 20–30 с), через NDK продукта — работает.
- **Цена пустого потока:** возраст кадра +12,5 мс при равной выдержке (18 → 30,7 мс; результат приходит вместе с кадром, а не на ~8 мс раньше); от размера/формата/целей не зависит, вендорские ключи (`RawCbSourceType`, `pipelineControl.*`, `EarlyPCRenable`, `statsconfigs.*StatsControl` в RAW-only) не помогают (решение 70). Ток ≈ +105 мА ABBA (решение 71). `dumpsys battery` «Battery current» в зонде показывает 0 — ток брать из `BatteryManager.CURRENT_NOW` (мА).
- **Регионы AF работают** (продукт `3a`): тап в разные точки → 0,9–3,5 дптр, разброс 2,4–2,5 дптр; тап сходится за 13–35 кадров; user context запроса доживает до колбэка NDK (0 потерь). Ручная 1/1000 → 0,996 мс через ~9 кадров; EV ±1 → ×1,94/×0,48; серия 4 кадра подряд.
- **Наш AWB на телефоне:** белый лист под тёплой лампой — 2683 K, ΔE76 ≈ 1,4 (уверенность 0,79); под холодным LED — 3766 K, Duv +0,017, ΔE ≈ 1,3 (уверенность 0,22 — близко к порогу 0,17: «зелёные» LED штрафуются тягой к локусу). Отличие от белой HAL 3–17 майред. Холодный старт скрывает 2 кадра. Статистика каждый 4-й кадр — цена «не различим» (было 55 мА на каждом кадре).
- Задержка видоискателя release p50 96 мс (07a: 77): +12,5 мс пустой поток + длинная выдержка ожившего AE в тёмной комнате (возраст кадра при приходе 47 мс против 30 в 05).

## GPU Adreno 740v2 под нагрузкой (сессия 16a, 24.11.2026; подробности — `results/16a.md`, правила — `mem:saturation_bench`)
- Возможности: subgroupSize 64 (64…128, subgroupSizeControl), shaderFloat16/Int16/Int8, storageBuffer16BitAccess и 8BitAccess (uniformAndStorage* — нет), shared memory compute 32 КБ, maxTexelBufferElements 134 млн, RTE и сброс денормалей в ноль (сохранения денормалей нет), VK_QCOM_image_processing, VK_QCOM_tile_properties, VK_EXT_shader_atomic_float, VK_KHR_fragment_shading_rate.
- Без root читаются `/sys/class/kgsl/kgsl-3d0/gpubusy` и зоны `gpuss-0…7`, `shell_front/frame/back`, `skin-msm-therm` (`/sys/class/thermal/thermal_zone*/{type,temp}`), частота GPU закрыта. В темпе vsync оба цену работы НЕ показывают (занятость ≈ 80 % и на голой камере; gpuss греет весь чип). Perfetto без root — только `android.gpu.memory`.
- Ток «до» (release, 60 Гц, ABBA 60 с): CALIBRATE весь продукт +442 ± 20 мА к камере без обработки (910–934 против 480), рисование UI со стеклом +287 ± 18, прибор waveform ≈ +27 (не различим); PHOTO +370 ± 32, UI +71 ± 11. Ток НЕ складывается из долей. CALIBRATE: light → critical за 12,5 мин (батарея 36 → 44 °C, задняя крышка до 50 °C).
- Полоса памяти ≈ 37 ГБ/с (копирование плоскостей f32). Компиляция compute-пайплайна видоискателя 145–180 мс, драйвер между запусками не кэширует.
- Дорого: размер кода фрагментного шейдера (стекло), исполняемые инструкции compute (ISP), `subgroupAdd`, конкуренция `atomicAdd` за одну ячейку, группа поперёк строк чтения (64×4 у повёрнутого видоискателя — ×5). Дёшево: выборки фона, `pow`, `imageStore`, чтение упакованного RAW10, `atomicAdd` без конкуренции. Не помогает: fp16/mediump, принудительный размер subgroup, плитки с ореолом в shared-памяти (медленнее чтения соседей из буфера).
- Компилятор шейдеров складывает иначе, чем RADV: «бит-в-бит на ПК» не переносится — проверять отпечатком выхода на устройстве.
- **С работающей камерой экран держит 60 Гц** при запросе 120 и удерживаемом касании — и при moderate–severe, и на холодном телефоне (31 °C, статус none: 60,1 Гц, дважды). Кто держит (система или приложение) — не выяснялось; решение 219: оставить 60, строку `display_120hz` на экранах с камерой не запускать. Без камеры (стенд V4) 120 Гц с касанием достигались.
- Ток «после» 16a с батареи (одна сцена, сборка до оптимизаций → новая, 60 Гц): PHOTO весь телефон 728 → 665 мА, наш GPU поверх камеры и экрана +280 ± 11 → +235 ± 2; CALIBRATE 849 → 692, +378 ± 67 → +246 ± 54 (статус severe, разброс велик), стекло UI +102 ± 9. **Камера и экран без нашей обработки — 430–470 мА, две трети тока** (вход сессии 16c). Абсолютные числа разных заходов несравнимы (ночной «до» дал +370/+442): сравнивать только внутри одного захода.
- Тепло: 25 мин CALIBRATE на новой сборке на зарядке — severe с 9-й минуты, батарея 34 → 41,5 °C («до»: critical за 12,5 мин).
- Кэш пайплайнов (`VkPipelineCache`) на Adreno: драйвер между запусками ничего не помнит (145–200 мс на вариант compute-шейдера ISP); с кэшем из файла — 0,7–1,1 мс на вариант, 11 вариантов фоном 0,35–0,44 с, запуск → первый живой кадр 0,59–0,73 с (без кэша 1,35–1,7). Данные всех пайплайнов приложения ≈ 0,37 МБ; `vkGetPipelineCacheData` 1,8 мс, запись 2,6 мс. Создание пайплайнов из двух потоков с общим кэшем (без `EXTERNALLY_SYNCHRONIZED`) работает.
- После сценария приложение остаётся на экране и греет телефон: между замерами `--stop-app-after`.
- Звуковой сигнал владельцу через adb без смены настроек: `adb shell am start -a android.intent.action.SET_TIMER --ei android.intent.extra.alarm.LENGTH 2 --ez android.intent.extra.alarm.SKIP_UI true` (таймер штатных часов, громкость будильника). Сигналить редко — только когда владелец нужен для оценки результата (решение 216).

## Vulkan / кодер
- Импорт без копий: `AImageReader` usage `GPU_SAMPLED_IMAGE` (0x100); `GPU_DATA_BUFFER` для RAW gralloc не выделяет (камера молча без кадров). RAW16 → `VkImage R16_UINT` storage; RAW10 → `VkBuffer` (AHB stride в байтах, 5120 для 4096). AHB props: format UNDEFINED, externalFormat 0. Acquire-fence приходит сигнальным; release через `AImage_deleteAsync` + sync_fd. Сумма GPU = CPU.
- Adreno 740, Vulkan 1.3.128; нет present_wait, cooperative_matrix.
- Vulkan swapchain прямо на входную surface `c2.qti.hevc.encoder.hdr`: 3840×2160, A2B10G10R10, цветовые пространства HDR10 PQ/HLG; 300/300 кадров, PTS через VK_GOOGLE_display_timing.
