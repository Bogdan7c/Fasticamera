# Сессия 14s: гистограмма и CIE-диаграмма охвата

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 14s плана `user/foundation/`: гистограмма и CIE-диаграмма охвата в разделе калибровки, на чистом следе 14r. Сначала прочитай `user/foundation/README.md` (решения 188–190, 252–253, 317–330), `results/14r.md`, `mem:saturation_bench`, потом этот файл. Код — на ПК. Телефон — глаза владельца и цена в конце.

## Зачем

Запрос владельца в 14r (решение 320): «не уступать Resolve и Final Cut» по полноте цвета. В 14r делаются дефекты, чистый след, вектороскоп «как у про» и яркостный след. Гистограмма и CIE вынесены сюда, чтобы цена и приёмка каждой части читались отдельно.

## Что известно до старта

- Новый прибор встраивается через шов типов (14h): вариант словаря `ScopeKind`, правило на CPU (`ScopeRule`), правило на GPU (`GpuScopeRule`), свой шейдер, если нужен. Подставная гистограмма из теста 14h уже считала на CPU и GPU бит в бит.
- Resolve: гистограмма RGB и YRGB; CIE 1931 xy и 1976 u′v′ с треугольником охвата проекта и вторым треугольником для сравнения. Final Cut: гистограмма, отдельной CIE нет, есть поиск цветов вне охвата (разведка 14r, источники — в `results/14r.md`).
- **Буквы цветов у целей вектороскопа (R, MG, B, CY, G, YL) — тоже здесь** (решения 326, 327): канал «подписи прибора» рендер → приложение → экран, как едет упор белого (`look_stops_publisher.rs` → `look_white_stops.rs` → `ScreenAction`). Им же CIE подписывает треугольники охвата. Положение букв считает эталон (`scope-model`) по решённому прибору — с охватом экрана, масштабом (`ycbcr_edge_chroma`, `oklab_range`) и зумом ×2 (решение 325); цель за краем — без буквы.
- **Бюджет цены — предел владельца +150 мА на прибор в разделе** (решение 328); после 14r прибор стоит +126 ± 16 мА — запас мал. Прибор поднимает частоту GPU, ток нелинеен от мс прохода: новые приборы мерить сразу током (`viewfinder-stage-budget --surface calibrate_screen --stages color_scopes`, батарея), стенд — только для сравнения проходов. Приборы считаются каждый второй кадр (решение 329), отсчёт с шагом несёт массу своего блока (`AxisResampling::carrying_pixels_per_hit`) — гистограмме и CIE брать тот же план отсчётов `ResolvedScope::planned_samples`.
- Разведка 14r по открытым источникам была неполной: страницы руководства Resolve не открылись. Перед кодом — второй, прицельный заход по руководствам Resolve и FCP и по руководствам колористов.

## Порядок

1. Вопросы владельцу одной пачкой: какие режимы гистограммы (RGB наложением, RGB секциями, яркость), какая CIE (xy или u′v′), какие треугольники (экран P3, sRGB, Rec.2020), сколько страниц в свайпе и в каком порядке.
2. Разведка по руководствам (без копирования чужого вида).
3. Архитектура, код, тесты на ПК: эталон `scope-model` — источник истины, GPU с ним в паритете. Для CIE — правило точек (линейный свет → XYZ → xy) и допуск, если нужна float-математика.
4. Телефон: глаза владельца, цена при насыщении против 14r.

## Критерий выхода

- Владелец принял гистограмму и CIE глазами на живом кадре.
- Паритет GPU с эталоном держится тестами, цена на телефоне записана рядом с 14r.
