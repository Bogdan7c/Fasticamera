# Сессия 08: автоматика 3A и домен ручных параметров

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 08 плана `user/foundation/`: заведи контракт 3A в `camera-core` — вендорские AF/AE через HAL (регионы, триггер фокуса, блокировка AE/AF, компенсация экспозиции), собственный AWB по статистике RAW из 07 с плавной адаптацией, и домен ручных параметров (ISO, выдержка, фокус, баланс, EV) с «авто/ручное» для каждого. UI здесь не делается. Сначала прочитай `user/foundation/README.md`, `results/04.md` и `results/07.md`.

## Зачем

Решение 9: фокус и экспозиция — вендорские, цвет — наш, всё за контрактом. Если «кто сейчас управляет экспозицией» размазано между UI, камерой и ISP, ручной режим (15) превратится в клубок условий. Здесь один владелец — `camera-core`.

## Архитектура

- **Контракт**: `FocusController`, `ExposureController`, `WhiteBalanceEstimator` — трейты с реализациями:
  - `VendorFocus` / `VendorExposure` — через запросы HAL;
  - `RawStatsWhiteBalance` — наш;
  - fake для тестов.

  Заменить любую часть своей — новая реализация трейта, без правки соседей.
- **Состояния 3A** как в iOS:
  - тап → фокус и экспозиция в точку (регион, триггер);
  - долгий тап → `AE/AF LOCK`;
  - вертикальный жест рядом с точкой → компенсация экспозиции.
  
  Здесь — машина состояний и команды, жесты — в 12.
- **AWB**:
  - оценка иллюминанта по статистике плиток (07) с ограничением на локус Планка и калибровку DNG камеры;
  - временное сглаживание: скорость адаптации — параметр, ориентир — поведение iOS из 09;
  - выход — коэффициенты в `IspParams`, а не в HAL;
  - подсказка HAL (`COLOR_CORRECTION_GAINS`) — только для диагностики сравнения;
  - **факт 07a (решение 55):** в нашей сессии из одного RAW-потока HAL баланс не считает — нейтральная точка `0/0`, коэффициенты `[1, 1, 1, 1]`. Сравнивать не с чем, и до 08 видоискатель зелёный. Свой AWB заменяет временную нейтраль `render-loop` (`isp_params::NeutralSource`), а единичные коэффициенты HAL не должны снова стать «нейтралью». При этом AWB HAL внутри работает: при старте нашей сессии провайдер камеры пытается записать свойство `vendor.oplus.camera.awb.pregain` (пример: «3706, 1.73, 1.00, 2.28» — CCT и коэффициенты R/G/B; запись отклоняется SELinux). Вендорские теги результата со статистикой AWB — кандидат для диагностики сравнения, если найдутся.
  - **факт 07a (цена):** статистика AWB в проходе видоискателя стоит ≈ 55 ± 12 мА из ≈ 119 мА всего ISP (A/B тока, окна 60 с). Частота и разрешение статистики — параметры AWB 08, а не константа прохода: например, раз в N кадров или по прореженной сетке, с замером тока до/после.
- **Профили 3A (V6 README)**: `Photo` и `Video`. Здесь реализуется `Photo`, но контракт с первого дня принимает профиль: скорость адаптации AE/AWB, допустимость скачков. Изменения `IspParams` интерполируются по времени, а не применяются скачком.
- **Серия с брекетингом (V10)**: намерение «N кадров с экспозициями [...]» в контракте `ExposureController` (покадровое управление `PER_FRAME_CONTROL`). Реализация — тест-сценарий на телефоне: заданные экспозиции приходят в результатах ровно на свои кадры.
- **Ручные параметры**:
  - `ManualControl { iso: Control<Iso>, shutter: Control<ExposureTime>, focus: Control<FocusDistance>, white_balance: Control<Cct+Tint>, ev: Control<ExposureBias> }`, `Control::{Auto, Manual(value)}`;
  - диапазоны — из `CameraCapabilities` выбранной камеры; переключение камеры перепроверяет значения (явный результат «значение ограничено до …», а не молчаливое обрезание);
  - чистая функция планирует запрос HAL по намерениям.

## Стоп-вопрос владельцу

Полуавтомат («ISO ручное, выдержка авто» и наоборот). В HAL ручной сенсор выключает вендорский AE целиком, поэтому оставшийся авто-параметр должен считать **наш** AE-цикл по статистике RAW. Варианты:
- (а) свой простой AE только для полуавтомата;
- (б) в v1 только «всё авто» или «всё вручную»;
- (в) свой AE везде.

Объяснить простым языком с рекомендацией, решение — в README.

## Тесты

- AWB: синтетические сцены под иллюминантами 2800K/4000K/5500K/6500K → оценка в пределах допуска; сцена с доминирующим цветом не уводит баланс за порог; скачок света → сглаженный переход за заданное время.
- Машина 3A с fake-HAL: тап → `Scanning → Focused/NotFocused`; блокировка переживает смену сцены; переключение камеры сбрасывает блокировку (как в iOS — сверить с 09).
- Ручные параметры: значение вне диапазона новой камеры → явный результат ограничения; `Manual(iso)` без `Manual(shutter)` ведёт себя по решению владельца.
- Телефон `device-smoke.sh 3a`: тап в точку → AF сходится, `LENS_FOCUS_DISTANCE` в результате меняется; ручная выдержка 1/1000 → в результате ровно она; AWB нейтральной карты под двумя источниками света → ΔE < порога.

## Критерий выхода

- 3A за контрактом, каждая реализация заменима. Вендорский AE/AF не трогает пиксели (проверено: ISP-выход зависит только от наших параметров и RAW).
- Решение владельца по полуавтомату записано.
