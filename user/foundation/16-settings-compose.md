# Сессия 16: настройки на Compose и схема config

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 16 плана `user/foundation/`: создай нейтральный crate `app-config` (владелец настроек: схема с версией, миграции, атомарная запись, битый файл → `.bak` + значения по умолчанию + предупреждение) и экран настроек на Compose в стиле iOS Settings по `scope-v1.md`. Compose читает и меняет настройки только через намерения шва. Сначала прочитай `user/foundation/README.md`, `results/02.md`, `results/14.md` и `docs/ios-camera/scope-v1.md`.

## Зачем

Настройки — второй мир UI (решение 5) и единственное место, где Kotlin что-то показывает. Если Compose начнёт сам писать файлы или читать поля Rust, появится второй владелец настроек. Владелец один — `app-config`. Решение «битый config → .bak + defaults + предупреждение» перенесено из fastiplayer как проверенная практика.

## Архитектура

- **`app-config`** (Rust, без Android):
  - `Settings` с версией схемы;
  - миграции по шагам;
  - атомарная запись (временный файл + rename);
  - события изменения для подписчиков (`camera-screen`, `CaptureService`).
- **Пункты** — из `scope-v1.md`. Например: формат HEIF/JPEG, RAW по умолчанию, сетка, уровень, зеркальный фронт, «сохранять настройки» (как iOS Preserve Settings: режим, панель, экспозиция).
- **Шов**:
  - `ShellEvent::SettingsChanged(SettingChange)` от Compose → `app-config`;
  - `ShellCommands::publish_settings(SettingsSnapshot)` → Compose;
  - Compose держит только снимок для показа.
- **Compose**: iOS-подобный сгруппированный список, шрифт и иконки из решения 09. Открывается из экрана камеры по 09 (или системным путём, если в iOS так).
- **Карта модулей README**: добавить `app-config` в карту и таблицу владельцев (правка README — в этой сессии).

## Тесты

- Миграции: файл каждой старой версии → текущая без потери значений. Файл новее нашей версии → не перезаписывается, сессия работает на defaults с предупреждением.
- Битый файл → `.bak` + defaults + событие предупреждения; повторный запуск не множит `.bak`.
- Атомарность: прерывание между записью и rename → остаётся старый корректный файл.
- Сквозной на телефоне: смена формата на JPEG в Compose → следующий снимок — JPEG; перезапуск приложения → настройка сохранена.

## Критерий выхода

- Один владелец настроек, Compose без собственной логики хранения. Пункты `scope-v1.md` работают сквозь до поведения камеры.
