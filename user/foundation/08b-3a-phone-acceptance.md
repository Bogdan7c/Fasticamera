# Сессия 08b: приёмка 3A на телефоне, закрытие 08

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 08b плана `user/foundation/`: прими на телефоне код сессии 08 (3A, пустой YUV-поток, наш AWB, ручные параметры, серия) в порядке из этого файла, исправь найденное по причине, допиши `results/08.md` и закрой 08 коммитом. Сначала прочитай `user/foundation/README.md` (решения 62–69) и `results/08.md`.

## Зачем

Код 08 готов и проверен на ПК (`scripts/ci-checks.sh all` = 0), но в середине сессии телефон отвалился от беспроводного `adb`. Приёмка на телефоне — часть критерия выхода 08 (`08-3a-manual-controls.md`, раздел «Тесты»). Пока она не пройдена, 08a (наш AE) не начинается: строить свою экспозицию на непринятом 3A нельзя.

## Условия

- Телефон разблокирован, экран включён, разрешение камеры выдано (`dev.fasticamera.debug` и `dev.fasticamera`).
- **Сцена освещена** (обычный дневной или яркий комнатный свет). В тёмной комнате зонд 08 упирался в потолок ISO 6400 / 16,7 мс — проверки холодного старта AWB и EV вернут «не проверить» по причинам, не связанным с кодом.
- Для пункта 4 — сцена «предмет в 15–25 см сбоку кадра, фон в несколько метров в центре», телефон неподвижен. Ставит владелец.
- Для пункта 5 — серая карта и два разных источника света (лампа накаливания/тёплый LED и дневной свет). Ставит владелец.
- Для пункта 6 — телефон на батарее (не на зарядке), условия замеров из README («Замеры на телефоне»).

## Порядок (каждый шаг — только после зелёного предыдущего)

1. **`scripts/device-smoke.sh hello`** (debug) — новые секции конфига (`camera.engine.three_a`, `camera.android.three_a_companion_stream`, `mains_frequency`, `viewfinder.white_balance`, `camera.scenarios.three_a`) разбираются, приложение стартует.
2. **Раунд 4 зонда `threea`** (`tools/device-probe`, уже собран, см. `mem:suggested_commands`). Пустой поток (YUV 640×480, без целей в запросах) на:
   - основной 16:9@60 (AE `[60,60]`);
   - ширике 4:3@60;
   - фронте 30;
   - логической 0;
   - каждый с AE и с `AE_MODE_OFF`.

   Плюс «RAW тот же» (режим сенсора, уровни, средние по каналам с пустым потоком и без, чередованием) и минутный прогон без целей.

   **Если на какой-то камере пустой поток ломает поток кадров** (настраивается, но 0 кадров — так ключи CamX ломали ширик), откат на отказ HAL этого не ловит. Тогда нужен список камер в конфиге, как у `vendor_frame_duration_override_cameras`. Это решение агента, сообщить в отчёте.
3. **`camera-stream`** (`--timeout 120`) — все 6 шагов с пустым потоком: к/с, RAW16, логическая 0.
4. **`3a`** (`--timeout 150`, debug и release):
   - `three_a_companion = active`;
   - `AF_STATE`/`AE_STATE` есть;
   - `results_without_request_context = 0` — опознание запроса через user context доживает до колбэка NDK. Если нет — запасной путь по номеру кадра из `onCaptureStarted`, описан в `camera-android/src/request_origin.rs`;
   - тап в центр сходится;
   - ручная 1/1000 → ≈ 0,996 мс;
   - 1/10 с → «ограничено длительностью кадра»;
   - EV ±1;
   - блокировка;
   - серия 2/4/8/16 мс по своим кадрам, не показана.

   **Регионы фокуса** — на сцене «близко/далеко»: `region_effect_diopters` в отчёте (разные точки → разные дистанции). Если HAL регионы игнорирует (в зонде 08 они в результате выглядели подменёнными на центр) — стоп-вопрос владельцу про тап-фокус в точку.
5. **`viewfinder`** (`--neutral-card`, серая карта, оба источника света по очереди):
   - картинка больше не зелёная;
   - ΔE серой карты до порога;
   - число скрытых кадров холодного старта (настоящее, не оценка);
   - разница нашей белой и белой HAL (`awb_vs_hal`).

   Сверить порог уверенности AWB `min_confidence = 0,17` (подобран на синтетике) и ширину серой полосы (Duv 0,04): на реальной сцене оценка не должна «залипать» в слабой уверенности.
6. **Цена в мА** (release, батарея, A/B ABBA по методике решения 45):
   - пустой поток против без него;
   - статистика AWB после прореживания (каждый 4-й кадр) против 07a (≈ 55 мА; мерить с `statistics_every_n_frames = 1` и по умолчанию).

   Пустой поток дорогой — вопрос владельцу (решение 62).
7. **Регрессия** (debug): `panic`, `raw-stream`, `camera-evict`, `render`, `ahb-import`, `gpu-fence`, `lifecycle`.

## Критерий выхода

- Все шаги зелёные или каждое отклонение — с найденной причиной и исправлением (тест, который падает без исправления) либо решением владельца.
- `results/08.md`: статус «выполнена», раздел «Проверено на телефоне» с цифрами, ограничения обновлены.
- Memories (`core`, `device/oneplus11-camera-facts`) — факты телефона по итогам.
- Коммит и push 08 + 08b (решение 44).
