# Сессия 10: ядро UI — дерево, вёрстка, жесты, пружины — отчёт

**Статус: выполнена.** Новые crate-ы `ui-core` (механика) и `ui-kit` (переиспользуемые элементы, решение 84) собраны и проверены на ПК: 311 тестов, `scripts/ci-checks.sh all` = 0. Новые crate-ы пока не входят в граф APK (их первым подключит экран камеры в 12). Из кода, который в APK входит, изменился только `shell-contract`: `HapticPattern` получил `Deserialize` (derive, поведение не меняется). Оба APK собираются в CI; smoke на телефоне (`hello`, `panic`) не запускался — телефон не был подключён к `adb` в момент закрытия.

- Дата: 19 ноября 2026.
- База: `7ac169d`.
- Объём: `ui-core` ≈ 7,1 тыс. строк продуктового кода, `ui-kit` ≈ 3,2 тыс., вместе с тестами ≈ 20,4 тыс.
- Новых внешних зависимостей нет (только `serde`, `thiserror` и словарь шва `shell-contract`). Context7 не понадобился: внешних API, кроме уже используемых `serde`/`thiserror`, сессия не касалась.

## Коротко, простыми словами

1. **«Как iPhone» — это физика, а не картинка.** Поэтому вся механика экрана камеры живёт в отдельном crate без телефона и без GPU и проверяется формулами. Пружины сверены с численным решением уравнения движения и с контрольными числами Apple, жесты — сценариями потоков касаний с точной последовательностью состояний.
2. **Элемент едет за пальцем** (слово владельца в этой сессии). Схватил — точка под пальцем стоит 1:1; ткнул в едущий — он замирает там, где его видно; отпустил — летит дальше со скоростью пальца без «ступеньки»; за краем — резинка; бросок выбирает конечную точку проекцией, как в WWDC18. Всё это закреплено сквозными тестами (карусель, шкала, панель).
3. **Время только снаружи.** Внутри нет «часов»: касания несут свою метку, кадры — время vsync. Один и тот же поток касаний и кадров даёт побитово одинаковый результат (тесты детерминизма).
4. **Без дублирования** (решение 84). Один движок прокрутки — и для карусели режимов, и для всех шкал (зум, EV, ручные параметры). Независимое ревью нашло дублирование и полу-применённые изменения — исправлены (подробности в «Дефектах» и «Self-review»).
5. **Числа — с паспортом.** Каждое значение по умолчанию — параметр конфига с источником и меткой происхождения (таблица ниже). Оценки помечены «подгонка, не Apple».

## Архитектура

| Слой | Crate | Владеет | Граница |
|---|---|---|---|
| Механика | `ui-core` | геометрия в pt, время, вход касаний, пружины, прокрутка, скорость, арена жестов, дерево, вёрстка, хит-тест, аниматор свойств, сцена | видит только `shell-contract` (касания, `MonotonicNanos`); guardrail `ui-core-mechanics-only` |
| Элементы | `ui-kit` | модели значений, K3 `SnapScale`, K4 `SnapCarousel`, K5/K6 `OptionPicker`/`IconToggle`, токены движения, плотности и хаптики | `ui-core` + `shell-contract` (хаптика); не знает камеру, GPU, Android — guardrail `ui-kit-not-camera` |

`ui-core`:
- `geometry` — `Point/Vector/Size/Rect/Insets` в pt, `f64`.
- `time` — `UiDuration` (целые нс), `AnimationClock` (время не идёт назад, счётчик `backwards_ticks`), `MotionPreference::{Full, Reduced}` — задел Reduce Motion.
- `input` — `PointScale` (ширина surface / 440 pt из конфига, решение 82), `PointerSample`, `UiInput::{Pointer, PointerStreamGap, Frame}`.
- `spring` — `Spring` (три пары параметров Apple → масса/жёсткость/затухание), аналитическое решение всех режимов с устойчивой окрестностью ζ = 1, `SpringAnimation` (прерывание «замена» с наследованием скорости), `AdditiveSpringAnimation` (политика «сложение», `interpolatingSpring`), `RestCriterion`, `Spring::for_motion` — **единственное** правило Reduce Motion.
- `scroll` — `ScrollAxis`: перетаскивание 1:1 → проекция броска → прилипание (`NearestToProjection` / `AdjacentOnly`) → резинка с обратной функцией; `reconfigure` атомарно меняет границы и точки; отмена = отпускание без скорости.
- `velocity` — LSQ2 по AOSP (`[reverse]`), без NaN.
- `gesture` — `GestureArena<I>`: `Tap` (в т.ч. двойной), `LongPress` (непрерывный: удержание → перетаскивание тем же касанием), `Pan` (ось/направление), `Pinch`, `Swipe`, `Press` (подсветка кнопки, уступает любому эксклюзивному жесту); отношения «требует провала», «одновременно», приоритет по глубине; таймеры тикают от кадров; данные пана — два смещения: от касания и от момента распознавания.
- `tree` / `layout` — арена с поколениями `NodeId`, свойства (прозрачность, масштаб, поворот, **визуальный сдвиг**), хит-тест как `UIView.hitTest` с учётом преобразований предков; вёрстка якорями к рамке/безопасной зоне и стеками.
- `animator` — свойства элементов едут пружинами, `freeze` — «схватить едущее там, где его видно».
- `scene` — `UiScene<I>`: дерево + жесты + анимации + часы; удаление только через сцену (снимает жесты и анимации удалённых), касания — в пикселях на входе. В доке — раздел «Ловушки» для 11–12: `layout()` после смены структуры (иначе хит-тест по старым рамкам); кнопка = `Tap` + `Press` (кнопка только с `Press` внутри видоискателя срабатывает вместе с фокусом); пан и свайп на одном элементе — только `pan.require_to_fail(swipe)` (медленный пан стартует не раньше 400 мс).

`ui-kit`: модели значений; общий привод `drive` (`AxisDrive::from_environment`) и `event_queue` для шкалы и карусели; **`pan::PanUpdate::from_gesture` + `apply_pan(time, update)`** — единственный вход «жест → элемент» (время — метка касания `GestureEvent::time`, не время кадра); K2 `button::PressTracker` (механика кнопки без вида); K3 `SnapScale`; K4 `SnapCarousel<T>`; K5/K6; токены.

Инварианты: время монотонно и приходит снаружи; удалённый элемент не «оживает» под старым id; таймеры жестов тикают от кадров; ни одного `HashMap`, влияющего на порядок; одно правило Reduce Motion; один движок прокрутки.

## Решения, принятые агентом (мелкие, обратимые)

- Время — `MonotonicNanos` из `shell-contract` (та же шкала у касаний и vsync), поэтому `ui-core` зависит от словаря шва.
- Внутри `ui-core` везде `f64` (точность сверки с формулами); рендер переводит в `f32` один раз.
- «Сложение» анимаций сделано, но для одной пружины оно математически совпадает с «заменой» (уравнение линейное); различие — только при смене пружины на лету. По умолчанию — «замена» (`motion.md` 1.4).
- Время успокоения `CASpringAnimation` критерий не подгонял: k 100, c 5 → 2,77 с (Apple ≈ 2,85); c 15 → 0,88 с (Apple «чуть больше 1 с»). Тест — грубая граница.
- Захват едущего элемента — в точке, **которую видно** (последний применённый кадр, как presentation layer UIKit), а не в физической точке пружины на момент касания; срабатывает на касании (`Press`), не после гистерезиса пана.
- Элемент начинает движение от точки распознавания жеста (без скачка на 10 pt гистерезиса) — параметр `DragOrigin`; что делает iPhone при медленном старте, проверить на эталонном iPhone.
- Хаптика карусели — в момент решения (отпускание/тап), а не по прибытии: пружина `camera_snap` едет ≈ 0,85 с, поздний щелчок оторвался бы от жеста.
- Прозрачность вне [0, 1] в дерево — ошибка; перелёт пружины обрезается аниматором при записи, сама пружина остаётся физической.
- **Системная отмена жеста** (`TouchPhase::Cancelled` = «сбросить без действия»): карусель возвращается пружиной к элементу, выбранному до жеста, без события выбора и вибрации — иначе системная отмена сменила бы режим камеры. Шкала при отмене — отпускание без скорости с магнитом: её значение (зум, выдержка) менялось вживую во время перетаскивания, откат к исходному дал бы лишний скачок. Альтернатива для шкалы (откат к значению до жеста) — если владелец захочет, это одна строка в `SnapScale::drag_cancelled`.
- Кнопка срабатывает по отпусканию внутри зоны отслеживания по событиям `Press`; `Tap` нужен только арбитражу (глубокий `Tap` кнопки отнимает касание у тапа видоискателя). Если нужно «срабатывает, только если выиграл `Tap`», — это изменение `PressTracker`.
- `HapticPattern` в `shell-contract` получил `Deserialize`, чтобы таблица хаптики `ui-kit` не копировала список паттернов.

## Дефекты, найденные по ходу, и их причины

| Дефект | Причина | Исправление и тест |
|---|---|---|
| Шкала в покое сама уезжала на другой шаг после смены пределов камеры | успокоившаяся пружина прилипания оставалась состоянием «пружина», и перепланирование перенацеливало её на ближайшую новую точку | в покое движение превращается в «покой»; `settled_content_stays_put_when_snap_points_or_bounds_change` (падал без правки) |
| Системная отмена: у шкалы без магнита, у карусели — с выбором | два разных пути отмены | движок: `ScrollAxis::cancel` = отпускание без скорости; шкала — магнит как при отпускании; карусель — возврат к прежнему выбору без событий (см. решения агента) |
| На шве «сцена → элемент» у шкалы и карусели разный порядок аргументов и не сказано, какое время брать | intent-методы писались в двух элементах отдельно | `PanUpdate` + `apply_pan(time, update)`, время — метка касания; сквозной тест от пикселей (`ui-kit/tests/scene_to_element.rs`) |
| `set_limits`/`set_entries` при ошибке на втором шаге оставляли модель и движок рассогласованными | применение до полной проверки | `ScrollAxis::reconfigure` на копии; тесты с отказом на втором шаге |
| Карусель искала точку возврата сравнением `f64 ==` | исход отпускания не нёс индекс | `ReturnsFromOverscroll { snap_index }` |
| Две копии правила Reduce Motion, три копии «оценка скорости → число», два типа перехода, копии обвязки шкалы и карусели, два пути выборки пружины, зеркало `HapticPattern` | пять пакетов писались параллельно | `Spring::for_motion`, `VelocityEstimate::or_zero`, `ScrollTransition`, `AxisDrive::from_environment` + `EventQueue`, `Spring::evolve_since`, `HapticSetting::Play(HapticPattern)` |
| Исчерпание id распознавателей давало дубликат; отказ удаления — тихий пропуск в release | `saturating_add`, `debug_assert!(false)` | явные ошибки `RecognizerIdsExhausted`, `Result` у `remove_node_recognizers` |
| Абсурдные пределы шкалы аллоцировали бы миллиарды рисок | нет бюджета | `ValueError::TooManyMarks` (предел 100 000 — инженерная защита) |

## Тесты

311 тестов, все — наблюдаемый результат. Главные:
- **Пружины**: контрольные точки Apple в обе стороны; аналитика против RK4 в 9 режимах (включая ζ = 1 ± 1e-6, перезатухание bounce −0,13); непрерывность через ζ = 1; прерывание на середине — позиция и скорость непрерывны; 60 и 120 Гц побитово равны; Reduced без перелёта.
- **Прокрутка**: бросок приезжает ровно в проекцию; резинка 2,74 / 52,02 / 340,65 при d = 960; возврат без скачков; захват во время возврата без скачка; прилипание к ближайшей к проекции; «только соседняя» листает ±1.
- **Жесты** (сценарии из плана, точная последовательность состояний и победитель): тап/пан по порогу (9 / 11 pt); долгий тап только кадрами; щипок с отрывом одного пальца (оставшийся палец не начинает пан); свайп режимов против вертикальной экспозиции; системная отмена и дыра потока; кнопка зума (тап / удержание → ведение / пан); тап против двойного тапа; `Press` (кнопка); удаление посреди жеста; глубина; затвор М2; детерминизм.
- **Скорость**: равномерная и равноускоренная траектория; торможение видно; рывок в конце гасится в 6 раз против разности двух точек; вырожденные → 0.
- **Дерево и вёрстка**: все якоря; привязка к низу при 956 и 982,67 pt (нижние элементы на месте, полоса сверху выросла на 26,67 pt); хит-тест с поворотом, масштабом, сдвигом, расширенной областью касания; поколения id.
- **Ведение за пальцем** (сквозные): карусель, шкала, панель — 1:1 на каждом кадре, без скачка на гистерезис, скорость при отпускании равна скорости пальца, захват едущего — на месте.
- **Шов сцена → элемент** (`ui-kit/tests/scene_to_element.rs`): касания в пикселях → `UiScene` → `Pan` → карусель: 1:1 с правильным знаком, без скачка на гистерезис, скорость при отпускании = −скорость пальца (3000 pt/с, допуск 1 pt/с), бросок листает ровно на ±1, ровно одно `SelectionChanged`; вертикальная шкала «солнце» — ровно 7 событий рубежей на медленном проходе; системная отмена через всю цепочку — без выбора.
- **Видоискатель** (`ui-core/tests/viewfinder_arbitration.rs`, таблица 1.2): «солнце» глубже меню вверх; вверх вне «солнца» — меню; вниз — ничей; горизонталь — режимы даже со старта на «солнце»; 2 пальца — щипок; второй палец отменяет «солнце»; тап — фокус; 0,5 с — блокировка; капсула режимов.
- **Кнопка** (`ui-kit/tests/button_press.rs`): подсветка сразу, увёл/вернул, отпустил снаружи — нет срабатывания, отмена, тап кнопки внутри видоискателя — кнопка, фокус `Failed`; ловушка «только `Press`».
- **ui-kit**: 1000 шагов по 1/3 EV туда и обратно — ровно 0; 1× ровно посередине между .5 и 2 на лог-шкале; медленный проход −2 → +2 EV — ровно 12 событий, один `RigidImpact` на нуле; бросок карусели 20 000 pt/с листает ровно на 1; один элемент (только PHOTO) — только резинка.

## Известные ограничения

- Путь хит-теста второго и следующих пальцев не используется: они идут кандидатам первого.
- У тапа нет предела длительности удержания.
- Смещение рамки через вёрстку пружиной не анимируется; для движения панелей — визуальный сдвиг (`TranslationX/Y`).
- Токены, плотность и размер области у живого элемента не меняются на лету (только `MotionPreference`).
- Карусель принимает тап по индексу; хит-тест по подписи — забота экрана (раскладку даёт `placements`).
- Не на телефоне: crate-ы не подключены к приложению до 12; smoke `hello`/`panic` после правки `shell-contract` не запускался (телефон не подключён).
