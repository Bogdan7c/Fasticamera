# Сессия 16a: весь GPU приложения под Adreno 740 — отчёт (в работе)

**Статус:** в работе. Готовы код замеров и замер «до»; оптимизации идут по шагам, каждая отдельным коммитом (решение 215). База — `6880ce5`.

## Коротко, простыми словами

1. **Греется весь конвейер, а не только раздел калибровки.** Release-сборка ест ≈ 900 мА и в PHOTO, и в CALIBRATE; камера без нашей обработки — ≈ 480–530 мА. Раздел калибровки доводит телефон до статуса critical за 12 минут.
2. **В CALIBRATE GPU занят на 96 % кадра на максимальной частоте**: ISP 6,67 мс + прибор 0,99 мс + показ 8,35 мс = 16,0 мс из 16,7. В PHOTO — 58 %.
3. **Самые дорогие работы — проход UI со стеклом (7,6 мс) и слитый проход ISP (6,7 мс).** Пирамида фона (0,4 мс) и компоновщик (0,25 мс) — мелочь.
4. Появился честный прибор цены — **стенд насыщения**: кадры работы идут подряд без показа, цена кадра = 1 / пропускная способность. DVFS её не размазывает.

## Решения владельца (сессия 16a)

Решения 210–216 в `README.md`: облегчаем весь конвейер в разы (210); порог — без числа, максимум под Adreno 740 без потери качества и поведения (211); продукт и V4 в одной сессии (212); допуск качества — до 1 младшего разряда 10-бит невидимого, фото бит-в-бит, упрощение стекла — крайняя мера (213); 120 Гц остаются, не рисуем лишнего (214); коммиты по шагам (215); телефон на зарядке, сигнал владельцу — редко (216).

## Факты об Adreno 740 этого телефона

- `subgroupSize` 64 (минимум 64, максимум 128), `shaderFloat16`, `shaderInt16`, `shaderInt8`, 16- и 8-битное хранение в storage-буферах; shared memory compute — 32 КБ; округление RTE и сброс денормалей в ноль для f16 и f32, сохранение денормалей не поддерживается.
- Есть `VK_QCOM_image_processing`, `VK_QCOM_tile_properties`, `VK_QCOM_render_pass_store_ops`, `VK_EXT_shader_atomic_float`, `VK_KHR_fragment_shading_rate`.
- Без root читаются `/sys/class/kgsl/kgsl-3d0/gpubusy` и тепловые зоны `gpuss-0…7`, `shell_*`, `skin-msm-therm`. Частота GPU закрыта. **Оба прибора в темпе vsync цену работы не показывают**: занятость держится у ≈ 80 % и на голой камере, и на ISP (драйвер подстраивает частоту), а датчики `gpuss` греет весь чип. В отчёте они — справочные колонки.
- Perfetto без root отдаёт только `android.gpu.memory`.
- При тепловом статусе moderate–severe экран остался на 60 Гц, хотя приложение запросило 120 Гц и «палец» удерживался на экране всё окно. Вероятно, горячий телефон не даёт 120 Гц (версия владельца); на остывшем не проверено.

## Дефекты, найденные по ходу, и их причины

- **Проверка окна «весь продукт» отвергала верное состояние.** При рисовальщике отладочной мозаики продукт UI не рисует и источнику кадр не даёт (ветка `Content::Mosaic`), а проверка ждала счётчик подавленных кадров. Ожидания теперь выводятся из пары «рисовальщик × подавление».
- **Состояние предыдущей строки протекало в следующую**: строка слала только те рычаги, которые трогает сама. Теперь рычаг, тронутый прежней строкой, возвращается в первом окне следующей.
- **Выход из CALIBRATE срывался после строки 120 Гц**: жест выхода выдавался, пока ещё держалось фоновое нажатие. Сценарий ждёт конец удержания плюс запас, драйвер не стреляет жестом поверх живого нажатия.
- **Адаптеры стенда давали предупреждения в сборке без тестовых фич** и держали синтетический RAW за тестовой фичей: release-сборка его бы не получила. Заведён держатель кадра `HostRawFrame` без тестовых фич.

## Известные ограничения кода замеров

- Стенд снимка подтверждает проявку обходным путём (маркерная работа, `2·слотов + 1` проявителей): граница модуля `photo` ради стенда не менялась. Цифра может быть слегка занижена; времён по проходам нет.
- Метки времени между проходами в работе показа слегка мешают конвейеризации: доли по проходам ориентировочные, цена кадра — по пропускной способности.
- Стенд насыщения на телефоне идёт на отдельном контексте GPU; поток рендера в это время показывает пустые кадры 60 раз в секунду.
- Приложение после сценария остаётся на экране и греет телефон: между замерами нужен флаг `--stop-app-after`.
