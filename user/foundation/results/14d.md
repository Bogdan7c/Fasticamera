# Сессия 14d: вспышка Off / On / Auto — отчёт

**Статус:** код готов и проверен на телефоне сценариями 22 ноября 2026; ручная приёмка владельца — раздел «Ручная приёмка» (идёт). База — `b393c82`, итог — в разделе «SHA итога». Решения владельца 153–161 (README). Картинка в миниатюре вынесена в подсессию 14g (решение 157).

## Коротко, простыми словами

1. **Вспышка работает: Off, On и Auto.** После нажатия телефон на мгновение включает фонарик (предвспышку), наш AE мерит сцену с ним и без него, считает выдержку и ISO под вспышку, гасит фонарик и делает один кадр со вспышкой. На телефоне «кадр захвачен» приходит через 0,45–0,5 с после нажатия.
2. **Кадр со вспышкой опознаётся по своему запросу, а не по времени.** Рендер берёт из кольца только кадр с меткой этого снимка. Подменить его другим кадром нельзя, а если он не пришёл — честный отказ.
3. **Освещённость проверяется по пикселям.** Зонд показал, что HAL может сказать «вспышка сработала», когда она не горела. Рендер сравнивает яркость кадра со сценой без вспышки; на телефоне проверку прошли все снимки со вспышкой.
4. **Белый — с кадра с фонариком** (тот же светодиод), подтяжка яркости — по плану движка. Кадры с фонариком видны в видоискателе, но не сбивают его AE и баланс белого.
5. **Auto решает наш AE**: если сцене без вспышки нужно больше «выдержки × ISO», чем порог из конфига, вспышка срабатывает. Экран только показывает выбор (значок «молния + A»), а решение читает приложение из статуса камеры.
6. **Значок вспышки появляется только у камер со вспышкой** (задние), на фронте его нет.

Инварианты:
- фонарик горит в повторяющемся запросе тогда и только тогда, когда последовательность в фазе «предвспышка»; любой выход его гасит;
- `FLASH_MODE` пишется в каждый запрос камеры со вспышкой, `Off` тоже (ключи HAL липкие); у камеры без вспышки ключа нет вовсе;
- на каждую команду снимка со вспышкой, дошедшую до движка, — ровно один итог `FlashStillFinished`; в рендере — ровно один итог снимка;
- разовая вспышка — не раньше паузы `torch_off_to_single_gap_ms` (100 мс) после выключения фонарика;
- замер «без фонарика» — только с кадров, снятых до запроса фонарика;
- кадр со вспышкой берётся только по своей метке запроса; кадры с фонариком и вспышкой не входят в сглаживание AE и AWB видоискателя;
- цепочка сроков проверяется при старте: камера (худшее 1,5 с) < рендер 1,8 с < служба 2,2 с < экран 2,7 с.

Формула (одна, `camera-core/src/engine/flash/plan.rs`): свет `L = 1 / P`, где `P` — «выдержка × ISO» для среднего серого; `L_вспышка = L_без + R · max(0, L_фонарик − L_без)`, `R = 1,87`; затем EV пользователя и делёж выдержка/ISO по пределам камеры.

## Что сделано (по модулям)

- **`camera-contract`**: модуль `flash` (словарь, тесты света кадра, ящик предвспышки), `RequestOrigin::FlashStill`, `ThreeAResultState.flash`, `CameraCapabilities.flash`, `ExposureDirective.flash`.
- **`camera-core`**: `engine/flash/` (решение, предвспышка с повторным замером при пересвете, пауза, отправка, итог, совет Auto, статус), `flash_config` (числа с метками, проверка границ, худший срок), `flash_status` (итог, совет, фаза, счётчики, наблюдатель), удержание нашего AE на время последовательности, взаимный отказ серии и вспышки, fake-бэкенд вспышки.
- **`camera-android`**: теги `FLASH_MODE`, `FLASH_STATE`, `FLASH_INFO_AVAILABLE` (сверка с NDK при сборке), разбор возможности и результата, `FLASH_MODE` во всех запросах, план разового запроса со вспышкой с ключами частоты и вендорскими.
- **`raw-frame-stream`**: выбор кадра со вспышкой по метке, обычные выборы его отвергают.
- **`scene-estimation`**: линейная «выдержка × ISO для среднего серого» (`exposure/linear.rs`), без защиты светов.
- **`render-loop`**: роли кадров видоискателя, линейные замеры предвспышки (статистика на каждом кадре во время предвспышки), белый кадров с фонариком отдельно от AWB видоискателя, стадия «жду кадр со вспышкой», проверка освещённости по RAW до «кадр захвачен», подтяжка по плану тем же квантованием, что у `k` видоискателя, конфиг `still.flash_*`.
- **`camera-screen` + `ui-draw`**: Auto выбирается, цикл Off → Auto → On → Off (iOS 26), карточка Auto / On / Off (iOS 27), значок `flash_auto` (Phosphor `lightning-a`, тот же закреплённый коммит и вес, что у `lightning`).
- **`photo-output`**: тег Exif `Flash` (0x9209): «сработала» — только кадр `FlashFrame`, прошедший проверку освещённости; у камеры без вспышки — «функции нет» (0x20).
- **`fasticamera-app`**: порт камеры для службы снимка, маршрут Off/On/Auto, наблюдатель отказов камеры → рендеру с поздней привязкой, факты экрана из возможностей активной камеры, цепочка сроков при старте, smoke `capture` с шагами `single_flash_on` (вердикт) и `single_flash_auto` (наблюдение), счётчики вспышки рендера в отчёте сценария.
- **Сроки:** служба «кадр захвачен» 1,5 → 2,2 с, экран 2,0 → 2,7 с — для всех снимков (отдельного срока для вспышки дёшево не сделать); срабатывают только при сбое.
- **Зонд** `tools/device-probe`: сценарий `flash` (фазы одиночной вспышки, фонарика, задержки фонарика, вспышки после фонарика, паузы).

## Найденные дефекты и их причины

1. **Вспышка сразу после фонарика не горит, но сообщает `FIRED`** (зонд, до кода). Причина — поведение HAL Qualcomm; лечится паузой ≥ 50 мс после выключения фонарика (взято 100) и проверкой освещённости по пикселям.
2. **Частичный кадр ширика портил замер «без фонарика»** (найдено рецензентом). Первый освещённый кадр ширика приходит с эхом `OFF` и считался «без фонарика». Движок обновлял этот замер и во время предвспышки, поэтому вклад фонарика выходил ≈ 0, а план — пересвеченным. Исправлено: замер «без фонарика» — только с кадров до запроса фонарика. Тест падал без исправления.
3. **Проверка освещённости сравнивала с последним кадром сцены, а не с тем, по которому считал движок** (рецензент). Исправлено: план несёт кадр замера сцены (`ambient_frame`), рендер помнит уровни по кадрам. Тест падал без исправления.
4. **Стадия ожидания кадра могла пережить свой срок, пока GPU занят** (рецензент): проверка срока стояла после ранних выходов. Исправлено, тест падал без исправления.
5. **Повторный замер при пересвете мог крутиться впустую** у предела выдержки и ISO и не продлевал срок (риск на 30 к/с). Исправлено, тесты.
6. **Замеры «без фонарика» будили движок камеры на каждом измеренном кадре, даже с выключенной вспышкой** (найдено проверкой debug-прогона, подсказка советника). Debug-серия на телефоне была хуже 14c: доля выброшенных кадров 0,30 и 0,23 против 0,188. Исправлено: вне предвспышки замер кладётся в ящик без толчка (`store_preflash_quietly`), движок читает его сам в начале предвспышки. После правки debug — 0,20 и 0,17 (горячий телефон, статус 3), release — 0,018 (было 0,08–0,09). Тест падал без исправления.
7. **Цепочка сроков не сходилась** после продления срока предвспышки (камера 1,5 с > служба 1,5 с). Исправлено: рендер 1,8 / служба 2,2 / экран 2,7 с, проверка при старте.

## Тесты (главное)

- **Контракт**: свет кадра по его результату (все сочетания режима и состояния), раздельные места замеров, ящик предвспышки не трогает предложения AE.
- **Движок камеры** (`engine/tests/flash_*.rs`, fake-бэкенд): полный путь (фонарик с экспозицией предвспышки → замеры → пауза: на 99 мс не отправлено, на 100 мс — `Single` с плановой экспозицией → `Fired` с планом; наблюдатель получил тот же итог); фонарик гаснет на каждом выходе (потеря сессии, фон, смена объектива, закрытие, сроки, отказ отправки); замер чужой камеры, чужого произведения и старого кадра не принимается; частичный кадр после запроса фонарика не становится замером сцены; повторный замер и его предел; каждый отказ — и итог команды, и итог снимка; AE не перестраивается во время последовательности; триггер фокуса во время предвспышки несёт фонарик; совет Auto и его порог; формула на известных числах.
- **Android**: `FLASH_MODE` в каждом запросе (повторяющийся, триггер, серия, разовый, тёплая камера — `Off`), коды результата, возможность камеры, метка запроса.
- **Рендер**: выбор по метке (найден / ещё нет / никогда не подставляется); кадр со вспышкой не показан, кадры с фонариком не двигают AE и AWB; линейный замер (одна сцена при P/2 и P — одно число); движок снимков на fake-GPU: кадр пришёл позже — `Secured` с `FlashFrame`, подтяжкой плана и белым фонарика; не пришёл — `FlashFrameNeverArrived`; отказ камеры — `FlashNotCaptured`; тёмный RAW — `FlashFrameNotLit`; отсоединение — `RendererStopped`; ровно один итог; на настоящем GPU (RADV) кадр со вспышкой доходит до `Secured`, проверка освещённости пройдена, видоискатель кадр не показал.
- **Экран**: цикл Off → Auto → On → Off, карточка из трёх вариантов, значок Auto, снимок несёт режим, без вспышки — `Off`; golden 19 из 19 без перегенерации.
- **Приложение**: маршрут Off / On / Auto × совет; `Begin` раньше команды камеры; отказ доставки команды → `FlashFailed` и один итог экрану; настоящий движок камеры + наблюдатель → отказ приходит рендеру с тем же номером снимка; цепочка сроков по каждому звену; сценарий `capture` с шагами вспышки через настоящую службу.
- Исправления самопроверки доказаны тестами, которые падали без них (проверено временным откатом).

## Известные ограничения

- **Сбой захвата кадра со вспышкой (`CaptureFailed` HAL) не завершает снимок сразу**: событие сбоя не несёт метки запроса. Снимок получает один честный итог `ResultTimedOut` через 400 мс. Чтобы ускорить, нужна метка запроса в событии сбоя (`camera-android` колбэк + граница `camera-core`).
- **Белый кадра со вспышкой — с кадра с фонариком.** Доля света вспышки (×1,87) больше, чем у фонарика, поэтому смесь «сцена + светодиод» во вспышке немного другая. Ошибка мала, когда вспышка преобладает.
- **Пересвеченный замер с фонариком после предела повторов** — план всё равно строится (снимок важнее), учитывается счётчиком `planned_from_clipped_torch`; кадр может выйти светлее.
- **Порог Auto** (`auto_fire_min_mid_gray_log2_seconds_iso` = 5,5) — `[estimate]`. В тестовой комнате Auto вспыхнул; светлая сцена на телефоне не проверялась — проверить владельцу.
- **R = 1,87** снят на прохладном телефоне; на горячем не мерилось.
- Кадр со вспышкой без спаренных метаданных (`Missing`) не опознаётся: видоискатель его покажет, снимок получит `FlashFrameNeverArrived`.
- Сворачивание посреди предвспышки на телефоне вручную не проверялось (покрыто тестами движка: фонарик гаснет, итог `SessionLost`).
- Повышение тёплой камеры посреди предвспышки с нашим AE тестом не покрыто (стенд тёплой камеры — с вендорским AE).
- **Ручная приёмка** (свет, ширик, фронт, взгляд владельца) — раздел «Ручная приёмка»; что не закроется сейчас, переходит в начало 14g.
- DNG со вспышкой на телефоне не снимался (шаг `single_flash_on` пишет HEIF); путь DNG тот же, что у любого снимка.
- Размеры модулей: `render-loop/src/thread/worker.rs` 747 строк, `still/engine_steps.rs` 673 — выше мягкого предела 700 / рядом, ниже жёсткого 800.
- Сроки «кадр захвачен» подняты для всех снимков (служба 2,2 с, экран 2,7 с); при исправной работе это не заметно.

Независимый рецензент (только чтение) проверил движок и рендер. Его находки 2–5 из раздела «Дефекты» исправлены. Ещё одну его находку главный агент сверил с фактами зонда и опроверг: кадры после выключения фонарика приходят с эхом `TORCH`, поэтому замер они не портят. Решения агента по ходу: у камеры без вспышки `FLASH_MODE` не пишется вовсе (лишний ключ мог бы сорвать запрос); совет Auto — без EV пользователя; кадры с фонариком показываются, но не сглаживаются; отказ доставки команды камере — отдельная причина `CommandNotDelivered`.
