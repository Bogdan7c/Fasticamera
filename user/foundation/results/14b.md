# Отчёт сессии 14b: раздел калибровки — ручки, модель основы, приборы, пресеты (только ПК)

**Статус:** закрыта на ПК (решение 194). Телефонная часть, подбор «Как глаз», выбор модели основы и цена на Adreno — 14j; виджет колёс цвета — 14b2 (решение 198).

**База:** `dfe5162`. **Итог:** `5d2de5c`.

## Решения владельца (195–203)

Записаны в README. Коротко:
- **195** — модель основы тона живёт в каждом пресете (пресет = основа + ручки), схема файла 2 → 3;
- **196** — сброс одной ручки — к значению редактируемого пресета, кнопкой «↻» у ручки (яркая = изменено, тусклая 44 % = как в пресете);
- **197** — имя пресета вводится системной клавиатурой (окно Kotlin);
- **198** — виджет колёс — отдельная подсессия 14b2;
- **199** — все шкалы списком, меню «шесть точек» на месте кнопки меню PHOTO;
- **200** — 8 цветных точек полос + 3 шкалы HUE / SAT / LUM;
- **201** — быстрый выбор пресета в PHOTO — карточка STYLES с рядом имён;
- **202** — альбомная раскладка — те же три зоны, поворот развёртки прибора по ориентации телефона;
- **203** — «чистая четверть» — кусок большого кадра: один видоискатель на весь экран.

Эталона Apple для раздела нет (кадров R27 / R28 не существует). Измерен только образец карточки Exposure — шкала и «↻». Всё остальное — придумано и помечено в коде (правило 96), владелец видел эскизы до кода.

## Что сделано

### Словарь и библиотека (`look-contract`, `look-presets`)
- **Словарь:**
  - `ToneBaseModel` (AgX / ACES / filmic / старая);
  - `LookRecipe { base, settings }` — то, что хранит пресет. Основа не входит в `LookSettings`, поэтому нейтраль «Честного» и «чистяка» по-прежнему без модели;
  - ручки как данные: `LookControl::{ToneBase, Knob(GlobalKnob), Band { band, axis }, Wheel { zone, part }}`;
  - намерения `SetToneBase` и `ResetControl`;
  - снимок для экрана `LookFacts`: текущие значения и значения пресета, список пресетов, полосы с цветом точки, ручки, недоступные основе, последняя проблема;
  - `CleanView`, `PresetEntry`.
- **Одно правило для «отличается» и для сброса:** `differs_from` = «скопировали у пресета — ничего не изменилось». После сброса метка «изменено» снимается гарантированно.
- **Библиотека:**
  - сброс одной ручки и смену основы библиотека делает сама;
  - исходы различимы: сброшено / уже как в пресете (`Unchanged`, записи нет) / `UnknownControl` (полосы нет в каталоге);
  - каталог (`CatalogEnvironment`) получает основу по умолчанию и список полос из конфига рендера.
- **Миграция схемы 2 → 3** — вторая продуктовая:
  - у своих пресетов появляется `"base": "agx"`, `edits` оборачивается в рецепт;
  - литерал заморожен: AgX — умолчание конфига на момент схемы 2;
  - перед первой записью — копия `…pre-v2`;
  - вход теста — настоящие файлы схемы 2, записанные кодом до правки (`look-presets/tests/fixtures/`).

### Основа на ходу (`render-loop`, `isp-vulkan`, `still-contract`)
- `ViewfinderCommand::SetToneBase`. Основа входит в ключ пересчёта параметров, параметры каждой модели — из той же секции тона (`tone_base_for`).
- **Проверка конфига теперь на всех четырёх моделях:** основу можно выбрать на ходу, поэтому кривой край ручки у невыбранной модели отвергается при старте.
- **Прогрев вариантов пайплайна:** вместе с вариантом под текущую основу строятся варианты под три других. Свайп по модели не создаёт пайплайнов посреди работы. Ёмкость кэша 14 → 16 (4 набора стадий × 4 модели), прогрев никого не вытесняет. Цена прогрева на телефоне — 14j.
- **Снимок берёт основу момента нажатия** (`StillPlan.tone_base`). Тест с мутацией: если подставить основу из конфига, тест падает.
- Стартовая основа — из активного пресета библиотеки.

### Приложение (`fasticamera-app`)
- **Рендеру уходит только разница:** `SetToneBase` и `SetLook` — что изменилось, неотправленное повторяется.
- **«Чистяк»:** нейтральные ручки на текущей основе, библиотека не трогается. Правки, пришедшие во время удержания, применяются при отпускании.
- **Факты вида экрану** (`look_facts.rs`) — снимком при изменении, как факты камеры:
  - недоступные ручки находит проба шва ручек `isp-model` по текущей основе, а не список, вписанный руками;
  - цвет точки полосы — OKLCh центра полосы; светлота и цветность — конфиг `camera_screen.band_swatch` с проверкой.
- **Проблемы:** отказ библиотеки и неудачная запись получают номер; новый номер = новая плашка на экране.
- **Ввод имени:** экран просит строку → брокер (`text_input_broker.rs`) → оболочка → окно Kotlin → ответ событием. Номер запроса экран узнаёт обратной связью исполнителя. Вытесненный запрос получает `Superseded`, его запоздавший ответ отбрасывается.
- **Установка экрана безусловно отпускает «чистяк»:** новый экран не оставит рендер на нейтрали.

### Экран (`camera-screen`, `ui-kit`)
- **Поведение режима — данные** (`ModeBehaviour`: есть ли затвор, снимает ли громкость, раскладка по ориентации).
  - CALIBRATE: затвора нет (`ShutterAbsentInMode`), громкость не снимает (`VolumeKeyIgnoredInMode`), раскладка следует за телефоном.
  - PHOTO не изменился: громкость снимает и при открытом Controls (решение 94).
- **Экран не хранит значений ручек:** намерение строится из `LookFacts.current`.
- **Раздел калибровки:**
  - колонка ручек на стекле: шапка с моделью основы (свайп), «↻» основы и CLEAN; список TONE / COLOR / BANDS прокручивается;
  - каждая ручка — шкала с «↻»; недоступная основе ручка тусклая и пальца не берёт;
  - точки полос и три шкалы выбранной полосы;
  - прибор на своей зоне — живая картинка 1:1 с размером запроса, свайп меняет тип;
  - правая верхняя зона пустая;
  - нижний ряд — капсула режимов и кнопка меню там же, где в PHOTO.
- **Альбомная раскладка:** весь раздел живёт в «глазных» координатах под одним повёрнутым узлом. Касания и паны переводятся обратно в глазные оси, прибор получает поворот развёртки.
- **Меню «шесть точек»:**
  - пункты PRESETS и SCOPE AXES;
  - карточка пресетов: ряд имён, NEW / RENAME / SAVE / DELETE; удаление — двумя тапами, второй показывает «CONFIRM» (придумано); «↻» — вернуть правки;
  - карточка осей вектороскопа.
- **PHOTO:** пункт STYLES в Controls, карточка с рядом имён и «↻».
- **Плашка проблемы** (K8): NAME TAKEN, SAVE FAILED, SAVES OFF, KEYBOARD UNAVAILABLE и др.; гаснет сама по сроку из конфига.
- **Без дублирования** (решение 84):
  - шкала Exposure вынесена в `ui-kit::ruler` (`RulerControl`, `FingerGate` — палец рождает действие, программа нет). Карточка Exposure побайтно та же: сверка списков рисования на ~70 кадрах;
  - `ui-kit::scroll_list::ScrollList` — вертикальный список и горизонтальный ряд;
  - общий ряд «таблеток» имён для STYLES и меню раздела.
- **Капсула режимов осталась измеренной** (221,4 × 48,9 pt, промежуток 35,4 pt). Соседняя подпись CALIBRATE видна и гаснет у края, как в iOS 27. Первую попытку исполнителя расширить капсулу под две подписи агент откатил как противоречащую замеру.
- **Кириллица в атласе шрифта** (А–я, Ё, ё): имена пресетов владельца — по-русски. Вёрстка кириллицы сверена с HarfBuzz до позиции каждого глифа. Символы вне набора (иероглифы, эмодзи) рисуются как «?», кадр не падает.
- **Шов «вид элемента управления — сменный»** (`ControlView::Rows`): колёса 14b2 добавятся новым вариантом.

## Найденные дефекты и их причины
1. **Сценарий `screen`: свайп возврата из CALIBRATE не менял режим.**
   - Причина: в PHOTO режим меняет горизонтальный свайп по видоискателю. В разделе на этом месте лежит колонка ручек, и свайп уходил в шкалу ручки.
   - Видоискатель в разделе открыт только в чистой зоне. Свайп по ней меняет режим, и это проверено.
   - Исправлено место свайпа в плане сценария, с объяснением в конфиге.
2. **Кириллические имена пресетов рисовались «?????»** — атлас был только ASCII. Исправлено расширением набора; тест сверки с HarfBuzz расширен.
3. **Капсула режимов расширялась под две подписи** — откат к замеру (см. выше).
4. **Экран, переустановленный при зажатом «чистяке», оставлял бы рендер на нейтрали.** Теперь установка экрана безусловно отпускает «чистяк» и шлёт активный вид. Тест с мутацией: при отключении падают 3 теста.
5. **«Чистяк», нажатый не пальцем (действием сценария или теста), отпускался на следующем же кадре.** Нашёл сквозной тест.
   - Причина: страховка кнопки CLEAN («состояние держится, а пальца нет → отпустить») срабатывала на каждом кадре. Задумана она только для пересборки шапки посреди удержания (поворот).
   - Теперь проверка идёт один раз, сразу после сборки шапки. Тест `a_clean_view_held_by_an_action_stays_held_across_frames` падает при старом поведении.
6. Дефекты независимого ревью — ниже.

## Отступления и решения агента
- **Поведение режима — данные в реестре**, а не проверки режима в коде затвора.
- **Удаление пресета — двумя тапами** («CONFIRM»), без таймера. Любое пользовательское действие между тапами снимает взвод. Придумано.
- **NEW открывает пустое поле:** имя активного пресета дало бы гарантированное «имя занято». RENAME открывает текущим именем.
- **Подписи кругов меню раздела — «LOOK» и «XY»:** подходящих значков в наборе нет, свои значки не рисовались. Пункт STYLES в Controls — текстом, как RAW.
- **Альбом:** видоискатель не поворачивается (сенсор поворачивается вместе с телефоном, картинка для глаза и так прямая), поворачивается только интерфейс раздела. Смена ориентации пересобирает раздел и сбрасывает прокрутку списка, без анимации.
- **Свайп режимов в разделе** работает по чистой зоне (в портрете — по оси поверхности) и по капсуле. Тап и долгий тап по видоискателю в разделе ничего не делают: фокуса и AE/AF Lock в разделе нет.
- **`ScopeDemandLost`** заложен в словаре, но приложение его не шлёт. Причина: рендер снимает спрос на прибор только при смене источника UI, а это всегда свежий экран (стартует в PHOTO). Доказано тестом.
- **Числа раздела — `[estimate]`** в `CalibrationConfig` / `CalibrationWidgetsConfig`:
  - доли зон: портрет — ручки 0,5 ширины, превью 0,62 высоты правой колонки; альбом — ручки 1/3, превью 0,5;
  - шаг ручки 0,1, крупная риска через 5;
  - таблетки, срок плашки 3 с, цвет точек полос.
- **`render-loop/src/config/tone.rs`** — 714 строк (мягкий предел 700) из-за `tone_base_for`. Модуль оставлен целым: выбор параметров модели — один связный инвариант с секциями тона.

## Независимое ревью
Два отдельных исполнителя только читали код: один — движок и приложение, второй — экран. Мои выводы им не передавались.

Чистыми признаны:
- миграция 2 → 3: копия до записи, `edits: null`, идемпотентность; файл схемы 3 у старого кода уходит в карантин, а не затирается;
- правило «отличается / сброс» и f32: NaN невозможен, −0,0 = 0,0;
- «чистяк» и снимок: снимок берёт вид библиотеки, а не показанный;
- основа на ходу, ёмкость кэша вариантов;
- сигнатуры JNI в Rust и Kotlin, коды команд и исходов;
- поворот развёртки CPU = GPU, порядок «зеркало, потом поворот»;
- решение 94 в PHOTO, геометрия альбома во всех четырёх ориентациях, капсула режимов.

Найдено и исправлено в этой же сессии. Каждое исправление — с тестом, который падает без него (проверено временным откатом):
1. **Два пальца на разных ручках в одном кадре затирали друг друга.** Экран слал `SetLook` — полный набор значений из фактов прошлого кадра. Причина в форме намерения, поэтому намерение и поменяли: точечные `SetKnob` / `SetBandAxis`, значения подставляет библиотека — единственный владелец.
2. **Альбом: свайп по чистой зоне шёл в осях поверхности.** Свайп «влево глазами» открывал меню, режим менялся вертикальным свайпом. Теперь у чистой зоны свой невидимый узел с паном в глазных осях раздела, свайпы видоискателя в разделе молчат.
3. **Запрет фокуса, AE/AF, зума и значков в CALIBRATE держал только виджет.** Теперь его держит редьюсер по данным режима (`CameraControls::Absent` → `NotAvailableInMode`). Отпускание жестов пропускается, чтобы жест, начатый в PHOTO, мог закончиться.
4. **Недоставленная команда при установке экрана оставляла рендер на нейтрали навсегда.** Теперь состояние «не знаю, что показывает рендер» явное, и повтор идёт на каждом кадре.
5. **Факты вида пересобирались дважды за кадр даже в PHOTO.** Теперь библиотека ведёт номер ревизии, факты пересобираются только при изменении, проба ручек кэшируется по основе.
6. **`ProblemDismissed` без номера мог погасить новую плашку, пришедшую в том же кадре.** Теперь действие несёт номер.
7. **Отказ постановки второго запроса имени терял ответ первого окна.** Экран теперь помнит первое окно, пока ждёт номер второго.
8. **Устойчивая ошибка раскладки раздела считалась отказом на каждом такте.** Теперь — один раз на смену ошибки.
9. **Kotlin: окно имени могло открыться после паузы Activity.** Теперь вместо показа сразу уходит `Cancelled` (проверка только сборкой, тестов Kotlin в проекте нет — 14j).

Оставлено как есть (ограничения):
- отказ платформы `PlatformCommandFailed(RequestTextInput)` не несёт номер запроса: при очень узком окне «A упал, B уже вытеснил A» отказ получит B;
- потерянный ответ окна (переполнение очереди событий) оставляет запрос открытым до следующего запроса;
- после неудачного прогрева варианта основы повторного прогрева нет;
- проверка файла пресетов не ловит вручную правленный файл с `EditedOnTop` при равных значениях;
- в ряду имён до 16 пресетов (`chip_pool_size`), лишние не выбираются из ряда — со счётчиком в диагностике.
