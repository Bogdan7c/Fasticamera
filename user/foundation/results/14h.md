# Итог сессии 14h: цветовые приборы, движок (только ПК)

Дата: 23 ноября 2026. Файл сессии — [14h-color-scopes.md](../14h-color-scopes.md). Решения владельца этой сессии — 188–190 в [README](../README.md) (раздел «сессия 14h»). База — `ee9b9d4`.

## Что сделано

Три прибора — **waveform, RGB parade, vectorscope** (оси Y'CbCr BT.709 или OKLab a/b) — считаются на CPU (эталон) и на GPU с паритетом счётчиков **бит в бит**. Есть путь от намерения экрана до готовой картинки прибора, которую UI рисует поверх превью без копии в CPU. Экрана раздела калибровки ещё нет — это 14b.

### Решения владельца (188–190)
- **188.** Два новых crate: `scope-contract` (словарь: тип прибора, оси, размер картинки, `ScopeIntent::{Show, Hide}`) и `scope-model` (эталон на CPU). Агент рекомендовал эталон модулем `isp-model`, владелец выбрал отдельный crate.
- **189.** Приборы меряют только картинку после вида — то, что на превью. Режима «до вида» нет. Сравнить с основой можно кнопкой «чистяк» (14b): она на лету переключает вид на нейтральный той же командой `SetLook`, второго прохода ISP нет.
- **190.** Всё в реальном времени на одном кадре. Прибор считается на каждом новом кадре камеры в том же командном буфере, что и показанный кадр. Рычаг `every_nth_frame` в конфиге оставлен только под бюджет, по умолчанию 1.

### Как устроено
```
экран: ScreenAction::Scopes(ScopeIntent) → Effect::Scopes
  → app scope_effects → ViewfinderCommand::Scopes(intent) → render-loop (настройки держат запрос)
кадр: ISP видоискателя → барьер чтения для compute → ColorScopes::record
  (очистка счётчиков → накопление atomicAdd → барьер → картинка прибора RGBA fp16, прямая альфа)
  → компоновка → UI: DrawItem::Image(ImageSource::Live(LiveImage::ColorScope)) читает картинку прибора
```
- **Вход прибора** — целые коды показанной части картинки видоискателя: окно содержимого с зеркалом фронталки, коды 10 бит, у запасного fp16 одно правило округления. Правило попадания построено так, чтобы GPU и CPU совпадали по построению:
  - waveform, parade и Y'CbCr — только целочисленная арифметика (проекции с весами в фиксированной точке);
  - OKLab — таблица декодирования, а float только `+ − ×` с `precise` (NoContraction). Кубический корень — своя итерация Ньютона без деления.
- **Типы приборов — данные.**
  - На CPU шов — трейт `ScopeRule`, на GPU — `GpuScopeRule` (шейдер накопления + параметры).
  - Waveform, parade и Y'CbCr используют один целочисленный шейдер с разными данными, у OKLab свой.
  - Новый прибор = вариант словаря + своё правило + свой шейдер. Подставной прибор из теста (гистограмма) считает на CPU и GPU бит в бит без правки соседей.
- **Владельцы.**
  - `scope-model` — формулы попадания и показа, сетка-разметка (уровни 0/25/50/75/100 %, центр, линия кожи, цели полос 75 %).
  - `isp-vulkan::scopes::ColorScopes` — GPU-ресурсы всех типов сразу: смена типа или осей свайпом ничего не создаёт, смена размера пересоздаёт только картинку.
  - `render-loop` `pipelines/scope_pass.rs` — когда считать и жизнь ресурсов: создание между кадрами, освобождение по fence слотов без ожидания на CPU.
  - `ui-draw` и `ui-render-vulkan` — «живая» GPU-картинка в UI.
- **Спрос живёт вместе с источником UI.** `Show` без установленного источника — явный отказ (`Rejected`). Установка, смена, снятие или паника источника снимают запрос и отпускают ресурсы. Одно состояние управляет и расчётом, и рисованием.
- **Конфиг** `render.viewfinder.scopes`:
  - `model` — размеры сеток (256), прореживание (2), усиление Y'CbCr, диапазон OKLab, вид следа и сетки;
  - `every_nth_frame` = 1;
  - `max_picture_side_px` = 2048.

  Все значения `[estimate]`.
- **Диагностика** `ViewfinderDiagnostics.scopes`:
  - запрос, состояние ресурсов (`Absent` / `Live` / `Retiring` / `Failed`);
  - проходы;
  - пропуски по причинам (темп, кадр не показан, ресурсы не готовы, нет входа, блокировка);
  - создания и освобождения, ошибки (один раз на смену запроса);
  - снятия спроса, время GPU;
  - режимы float32 устройства (`shaderRoundingModeRTEFloat32` и денормали).

## Замеры (RADV, Radeon 780M; не цена на Adreno — её мерит 14b)
Картинка 1080p, сетки 256, шаг прореживания 2, медиана из 8 прогонов. Накопление включает очистку счётчиков.

| Прибор | Накопление, мс | Картинка прибора, мс |
|---|---|---|
| waveform | 0,175 | 0,063 |
| RGB parade | 0,497 | 0,069 |
| vectorscope Y'CbCr | 0,289 | 0,081 |
| vectorscope OKLab (sRGB / P3) | 0,292 / 0,237 | 0,081 / 0,080 |

Закрытые приборы стоят 0: проход не записывается, ресурсов нет.

## Тесты, которые закрепляют работу
- **Правила на синтетике** (`scope-model`, 64 теста):
  - горизонтальный градиент даёт диагональ на waveform;
  - пересвет (1023) попадает в верхний ряд, 0 — в нижний;
  - серый даёт три одинаковые плоскости parade;
  - все 1024 серых кода попадают ровно в центр вектороскопа на обеих осях и на обоих экранах (sRGB, P3);
  - полосы 75 % ложатся в клетки, посчитанные независимо в f64;
  - зеркало переворачивает столбцы, прореживание считает ровно задокументированные отсчёты;
  - подставной прибор проходит через общий `accumulate`;
  - картинка прибора: прозрачный фон, след по log2, секции parade, сетка на уровнях;
  - каждая плохая настройка даёт свою ошибку.
- **Паритет CPU = GPU бит в бит** (`isp-vulkan`):
  - матрица из 6 сцен, 2 форматов входа, 5 правил, с зеркалом и без, шагов 1/2/3, при окне меньше ёмкости (в «хвосте» лежат «ядовитые» пиксели);
  - настоящий ISP видоискателя на 4 реальных RAW-кропах, тот же командный буфер;
  - картинка прибора против эталона — допуск 2e-3, измерено 7e-4;
  - вход прибора не меняется;
  - смена типа и осей не создаёт pipeline;
  - подставной прибор на GPU.
- **Живая картинка в UI** (`ui-render-vulkan`):
  - пиксели совпадают с эталоном ≤ 2/255 на sRGB и P3;
  - картинка без перевода sRGB → P3, в отличие от обычной;
  - прямая альфа;
  - отсутствующая картинка ничего не рисует и считается, кадр не падает;
  - обычные картинки (golden) не изменились.
- **Рендер** (`render-loop`, `vulkan_scopes*.rs`):
  - счётчики каждого кадра равны эталону по прочитанной картинке видоискателя ЭТОГО кадра, ровно один проход на новый кадр;
  - **инвариант 1**: пиксели видоискателя и статистика AWB одинаковы с приборами и без;
  - **инвариант 2**: после `Hide` проходов нет, объекты GPU (pipeline, layout, модули, наборы, пул запросов) вернулись к исходным;
  - запись кадра не создаёт объектов GPU (ресурсы готовятся между кадрами);
  - снятие спроса при установке, смене, снятии и панике источника;
  - `Show` без источника — отказ без ресурсов;
  - смена типов и осей, темп `every_nth_frame`;
  - постоянная ошибка сообщается один раз.
- **Сквозной** (`fasticamera-app/tests/scopes_end_to_end.rs`): настоящий `reduce(ScreenAction::Scopes)` → исполнитель приложения → рендер. Проверено:
  - счётчики того же кадра совпадают с эталоном;
  - картинка прибора совпадает с `scope_model::render`;
  - UI нарисовал живую картинку;
  - `Hide` отпускает ресурсы, UI считает элемент отсутствующим без сбоя;
  - оси OKLab доходят до GPU.
- **Временные поломки**: квантование `+0,5 → +0,49`, два шага Ньютона вместо трёх, ветка «уже в цветах экрана» в шейдере UI, «Hide не отпускает», сброс ресурсов сразу без fence, отключённое снятие спроса, создание ресурсов в кадре, повтор ошибки каждый кадр, порядок проверок в `record`, «исполнитель всегда шлёт Hide». Каждую ловит тест.

## Отступления и решения агента
- **Вектороскоп Y'CbCr на экране P3** — коэффициенты BT.709 применяются к кодам сигнала, как в видеомонтаже: прибор меряет сигнал, а не колориметрию. На sRGB это ровно BT.709. Цели полос 75 % и линия кожи (123°) стоят на своих местах.
- **Яркость waveform** — те же веса BT.709 по кодам.
- **Полный размах цвета** ложится на `size/2 − 1` клетки от центра, чтобы 100 % красный и синий оставались внутри сетки.
- **Линия кожи в OKLab** считается через то же правило от цвета кожи из настройки (`[estimate]`).
- **Бит в бит у OKLab держится на допущениях**: драйвер по умолчанию округляет float32 до ближайшего чётного и не встречает денормалей. Денормалей нет по построению: минимум таблицы ≈ 7,6e-5, у корня порог 1e-30. На RADV снятие `precise` тест не ломает: драйвер и так не сливает операции. Поэтому `NoContraction` на всех 104 float-операциях проверен по SPIR-V (`spirv-dis`). Факт RTE устройства виден в диагностике.
- **Ошибка GPU во время записи** блокирует приборы до смены запроса (одна ошибка, без повторов каждый кадр). Отказ до первой команды оставляет прошлую картинку.
- **Удержанный или чёрный кадр** (смена объектива) не меряется. UI показывает последнюю картинку прибора.
- **`ImageInstance` UI** вырос с 80 до 96 байт (поле цветового пространства источника).

## Независимое ревью
Отдельный исполнитель только читал код, мои выводы ему не передавались. Он построчно сверил GLSL с эталоном: порядок операций, знаковые сдвиги, полуоткрытые интервалы, раскладку матриц и таблицы. Нарушений паритета, барьеров и показа не нашёл. Риски и мелочи исправлены в этой же сессии:
- приборы считались бы без источника UI;
- ресурсы создавались внутри записи кадра (рвало бы vsync);
- постоянная ошибка писалась в лог каждый кадр;
- порядок «проверки → изменение» в `record`;
- отказ до команд прятал картинку;
- числа в шейдерах без связи с Rust: теперь размер группы задаётся специализацией, остальное сверяет тест;
- молчаливый запасной вариант в `trace_row_base` стал ошибкой;
- тихий пропуск прохода теперь считается;
- допущение RTE задокументировано.

4. **Порядок экрана**: `Show` — после установки источника UI и повторно после переустановки экрана. Отказ `Rejected` виден только в диагностике рендера.

6. **Y'CbCr на коэффициентах BT.709 по кодам P3** — привычно ли владельцу. OKLab — второй вариант в меню.

## Найденный попутно дефект
Тест `vulkan_ui_overlay_picture::an_oversized_picture_fails_the_ui_frame_honestly…` (14g) падал примерно в одном прогоне из 40, на базовом коммите тоже. Причина: тест сравнивал снимок ВСЕХ живых объектов GPU, а пул fence-ов показа (`PresentFencePool::begin_present`) растёт лениво по таймингу движка показа. Исправлено: сравниваются только виды, из которых состоит картинка (Image, ImageView, DeviceMemory, Buffer) — тем же помощником, что у соседнего теста. После правки — 40/40 зелёных.
