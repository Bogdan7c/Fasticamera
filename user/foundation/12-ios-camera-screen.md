# Сессия 12: экран камеры iOS 26

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 12 плана `user/foundation/`: создай crate `camera-screen` — экран камеры по спецификации `docs/ios-camera/` и утверждённому `scope-v1.md`: верхняя панель, маска соотношения сторон, переключатель режимов, затвор, миниатюра, панель настроек, квадрат фокуса с AE/AF LOCK, ползунок экспозиции, поворот иконок по ориентации. Экран отправляет намерения в `camera-core` и в сервис снимка, сам ничего не вызывает. Переключение камер и зум — в 13, снимок — в 14 (здесь fake-сервис). Сначала прочитай `user/foundation/README.md`, `results/08.md`, `results/11.md` и `docs/ios-camera/`.

## Зачем

Здесь механика (10), рисование (11), видоискатель (07) и 3A (08) впервые собираются в то, что видит владелец. Главный риск — превратить `camera-screen` в «бог-модуль», который знает всё. Поэтому экран владеет только состоянием экрана, а с остальными говорит намерениями.

## Архитектура

- **`ScreenState`** — единственный владелец того, что на экране:
  - режим;
  - открыта ли панель настроек;
  - состояние вспышки, RAW, таймера, соотношения;
  - положение квадрата фокуса;
  - видимость ползунка экспозиции;
  - ориентация иконок.

  Изменения — через `ScreenAction`. Обработка — чистая функция `(state, action) → (state, Vec<Effect>)`.
- **Эффекты** (`Effect`) — намерения наружу: `CameraIntent` для `camera-core`, `CaptureIntent` для сервиса снимка, `HapticPattern`, `OpenSystemGallery`. Исполняет их `fasticamera-app`, не экран.
- **Построение дерева**: из `ScreenState` → дерево `ui-core` со стилями стекла из 11. Анимации переходов — пружины из `motion.md`.
- **Режимы в карусели** — по решению владельца в 09 (рекомендация — только реализованные).
- **Файлы**: каждый виджет — отдельный модуль (`shutter_button`, `mode_carousel`, `top_bar`, `controls_drawer`, `focus_indicator`, `exposure_slider`, `thumbnail`). Предел 700/800 строк.

## Тесты

- Чистая функция экрана: каждое действие из `behavior.md` → ожидаемые состояние и эффекты.
  - Пример: тап по видоискателю → `CameraIntent::FocusAndExposeAt(point)` + квадрат фокуса.
  - Пример: долгий тап → `Lock` + баннер «AE/AF LOCK».
  - Тап по затвору при открытой панели — по спецификации 09.
- Golden на ПК: ключевые состояния экрана поверх фиксированного фона — с допуском.
- Смена ориентации: иконки поворачиваются пружиной, раскладка не меняется.
- Телефон `device-smoke.sh screen`: экран поверх живого видоискателя, 120 Гц без пропусков в сценарии «свайпы режимов + тапы фокуса + панель» (скриптовые касания через `input`), тап фокуса доходит до HAL (результат запроса).

## Ручная приёмка владельцем

Владелец сравнивает экран с эталонными видео из 09 (ссылки в `docs/ios-camera/`). Каждое замечание — пункт в отчёте: исправлено или вынесено с причиной.

## Критерий выхода

- Экран соответствует `scope-v1.md` (без зума, камер, снимка и ручного режима). Экран ничего не вызывает напрямую (guardrail: `camera-screen` не зависит от `camera-android`, `gpu-vulkan`, `android-shell`).
- Приёмка владельца пройдена или замечания разнесены по сессиям.
- Виджеты собраны из элементов `ui-kit` (решение 84, `docs/ios-camera/components.md`): в `camera-screen` нет своих жестов, физики и рисования там, где их даёт `ui-kit`; числа — только в токенах.
- Строки `docs/ios-camera/feature-map.md` с сессией 12 (решение 83) — задел сделан: реестр режимов (М1), машина состояний затвора (М2), набор инструментов как данные (М3), слой «фон вне кадра», событие клавиши громкости.
