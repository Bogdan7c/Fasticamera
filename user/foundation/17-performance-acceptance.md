# Сессия 17: замеры, тепло и итоговая приёмка

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 17 плана `user/foundation/`: проведи итоговые замеры Fasticamera против системной камеры OnePlus (холодный старт до первого кадра, задержка видоискателя, задержка затвора, время переключения камер, стабильность к/с, тепло и расход батареи за 10 минут), разберись с корневой причиной каждого существенного отставания, проведи приёмку владельцем по `scope-v1.md` и подготовь бэклог следующих планов. Сначала прочитай `user/foundation/README.md` и все `results/`.

## Зачем

План заявляет высокую производительность. Итог надо подтвердить цифрами в одинаковых условиях, а не ощущением. Отставание от системной камеры — не провал, если причина найдена и записана. Провал — если она не найдена.

## Методика (уточнить в начале сессии, при неоднозначности — вопрос владельцу)

- **Условия**: телефон остыл, одинаковые заряд, яркость и сцена; 120 Гц; чередование «наша / системная», три повтора.
- **Холодный старт**: `am start -W` и время до первого показанного кадра видоискателя (наш маркер в логе; у системной — по `dumpsys gfxinfo` или видеосъёмке экрана).
- **Задержка видоискателя** («стекло-стекло»): на мониторе ПК бегущий таймер в мс, телефон снимает монитор, третья камера (веб-камера ПК) снимает и монитор, и экран телефона. Методику подтвердить у владельца — нужна веб-камера.
- **Задержка затвора**: нажатие (событие касания) → время сенсора выбранного кадра; у системной — по видео с таймером.
- **Переключение камер, к/с, пропуски** — из счётчиков приложения.
- **Тепло и батарея**: 10 минут видоискателя 4K60, `dumpsys battery` и `thermalservice` в начале и в конце, троттлинг GPU (если виден в Perfetto).

## Что сделать

1. Замеры, таблица `Что | Fasticamera | Системная | Комментарий`.
2. Для каждого отставания больше порога (порог согласовать) — корневая причина с доказательством: трасса Perfetto, счётчик, эксперимент с откатом. Исправление — отдельной сессией `17a` при необходимости, не смешивая с замером.
3. Приёмка владельцем по `scope-v1.md`: каждая функция — «принято / замечание».
4. Проверка задела V1–V10 из README: каждое требование — «выполнено (доказательство) / нарушено (что чинить до плана `video`)».
5. Подготовка плана `video` (решение 16): цифры запаса GPU и тепла (V4), факты C8 из 00 → черновик README нового плана `user/video/` для сессии планирования с владельцем.

## Критерий выхода

- Таблица замеров с методикой, каждое отставание объяснено.
- Приёмка владельца, итог плана в README (раздел «Итог плана»), memories приведены в порядок (`mem:core` — граф ссылок, не журнал).

Memories: `mem:core` и memories всех доменов.
