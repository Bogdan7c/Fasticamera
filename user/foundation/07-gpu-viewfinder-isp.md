# Сессия 07: ISP видоискателя на GPU

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 07 плана `user/foundation/`: создай `isp-vulkan` с конвейером видоискателя (вариант `Preview` из `isp-model`), сверь его с эталоном на ПК, выведи живой видоискатель из RAW на экран телефона в правильном цветовом пространстве, кадрировании и ориентации и отдай изображение видоискателя как `BackdropSource` для будущего стекла. Сначала прочитай `user/foundation/README.md`, `results/05.md` и `results/06.md`.

## Зачем

Решение 8: видоискатель только из RAW через наш ISP. Он должен успевать за сенсором (до 60 к/с) с запасом под UI и стекло на 120 Гц. Каждая лишняя полноэкранная проходка — минус запас.

## Наследство

- 05: `RawFrameLease`, импорт, fence-ы, визуализация мозаики (заменяется настоящим ISP).
- 06: `IspParams`, стадии `Preview`, формулы и допуски.
- 03: headless-стенд для паритета.

## Архитектура

- **Слитый compute-проход**: уровни → баланс → демозаик 2×2 → цвет → тон → OETF. Один проход, запись в изображение видоискателя. Вычисления в fp16, где это не портит точность; где портит — fp32 (решать замером паритета, а не догадкой).
- **Выход**: `ViewfinderImage` в рабочем пространстве экрана.
  - Display P3, если swapchain его поддерживает (`VK_EXT_swapchain_colorspace` проверить в vkjson и в 03), иначе sRGB с явной записью в отчёте.
  - Кадрирование под соотношение и зум — параметр `ViewfinderCrop` (использует 13).
- **`BackdropSource`** (нейтральный тип в `gpu-vulkan`): изображение + fence готовности + номер кадра. Стекло (11) читает его и не знает, что это камера.
- **Статистика для AWB (08)**: в том же проходе — сумма каналов по плиткам с исключением пересветов в маленький буфер. Это не отдельный проход по полному кадру.
- **Показ**: видоискатель обновляется с частотой сенсора, композиция с UI — на 120 Гц. Между кадрами сенсора показывается последний `ViewfinderImage` — без повторной обработки.

## Тесты

- Паритет на ПК: один и тот же синтетический и реальный кроп через `isp-model::Preview` и `isp-vulkan` → max Δ и доля отличающихся пикселей в пределах допуска. Каждое расхождение объяснено.
- Каждая ручка `IspParams` (баланс, экспозиция, кривая) отдельно → совпадение с эталоном.
- Кадрирование и ориентация: метка в углу RAW-кадра оказывается в ожидаемом углу экрана для всех поворотов дисплея.
- Статистика AWB: известная синтетика → известные суммы, пересвет исключён.
- Телефон `device-smoke.sh viewfinder`: к/с видоискателя = к/с сенсора, GPU-время прохода ≤ бюджета (параметр, цель — меньше 3 мс на 4K-входе), кадр не чёрный, цвет нейтральной карты в пределах допуска.

## Замер

- GPU-время прохода (Perfetto/AGI), задержка «сенсор → экран», тепло за 10 минут.
- Сравнение с системной камерой по ощущению задержки — описание, без цифр соперника, если их не снять честно.
- **Запас под видео (V4 README)**: отдельный стенд — качественный демозаик полного кадра 4096×2304 + простой временной шумодав «на пробу» каждый кадр на 60 к/с, вместе с UI на 120 Гц. GPU-время, тепло за 10 минут. Это цифра для плана `video`, в продукт не встраивается. Выход ISP идёт через нейтральный «приёмник кадра» (V5), чтобы позже подключить кодер без переделки.

## Критерий выхода

- Живой видоискатель из RAW на телефоне, паритет с эталоном подтверждён, 0 CPU-копий.
- `BackdropSource` и буфер статистики готовы для 08 и 11.
