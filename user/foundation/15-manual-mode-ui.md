## Зачем

В штатной камере iOS ручного режима нет, а у нас он в объёме v1 (решение 4). Значит, его надо **спроектировать** так, чтобы он выглядел родным для iOS 26, а не приклеенным. Ближайшая родная идиома — наложение Camera Control (iPhone 16+): стеклянная капсула со шкалой, выбор параметра свайпом, тики хаптики.

## Архитектура

- Новые виджеты в `camera-screen` (`manual_dial`, `manual_parameter_picker`, индикаторы) — отдельными модулями.
- Колесо — общий виджет с колесом зума из 13. Шкала, тики и пружина прокрутки — одна реализация, разные шкалы.
- Шкалы:
  - выдержка — стандартный ряд (1/8000 … 1/2 … 1 с) в пределах `CameraCapabilities`;
  - ISO — ряд 1/3 ступени;
  - фокус — диоптрии с подписью расстояния (калибровка `APPROXIMATE` — подпись «≈»);
  - баланс — Кельвины + оттенок: панель делает план `user/white-balance/` (сессия 02, решения 239 и 240), здесь она переиспользуется.
- Значения отображаются по возможностям **текущей** камеры. Смена камеры → пересчёт и явное ограничение (из 08).
- Гистограмма и пикинг (если в v1) считаются на GPU в проходе видоискателя или рядом, без полного лишнего прохода.

## Дефект из 13c: компенсация EV в минус при большом пересвете

Найден ПК-тестом 13c (`simulation_clipping_tests.rs`), старый — из 08a, есть и с прежним лог-средним; владелец: «добавь в релевантную сессию». Когда больше ≈ 35 % веса кадра пересвечено (большое яркое окно), замер переходит в полосу «частичный пересвет» с правилом «экспозицию можно только снижать»: нужная ≤ выдержка кадра. Но кадр снят уже с компенсацией, а замер сравнивает с ним цель для EV 0. При EV −1 цель каждый раз режется вниз, движок снова делит её на 2, и кадр ступеньками уходит в чёрное (симуляция: ×0,00 вместо ×0,5).

- Причина — у владельца состояния: `scene-estimation::exposure::measurement` (полоса `Partial`) не знает компенсации кадра. Правило должно сравнивать с выдержкой кадра, приведённой к EV 0. Компенсация кадра видна по указанию движка, но кадры отстают от запроса на 7–8 кадров — сначала спроектировать, откуда замер берёт компенсацию именно этого кадра.
- Тест: тот же перебор окна, что `ev_compensation_doubles_and_halves_the_exposure_with_an_always_white_window_in_frame`, но с окном 35–80 % веса (сейчас тест ограничен полосой «норма»): EV +1 → ≈ ×2, EV −1 → ≈ ×½; без исправления EV −1 даёт ×0.
- Связь с UI этой сессии: колесо EV — первый путь, которым пользователь попадёт в дефект.

## Тесты

- Шкалы: ряды значений в пределах реальных характеристик каждой камеры (фикстура 00); привязка к ближайшему шагу.
- Колесо: бросок → остановка на шаге; тики по числу пройденных шагов.
- Сквозной на телефоне: выдержка 1/1000 и ISO 400 через UI → в результате запроса HAL ровно они; снимок → EXIF содержит их же.
