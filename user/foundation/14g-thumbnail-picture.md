# Сессия 14g: настоящая картинка последнего снимка в миниатюре

Приложи этот файл и скопируй абзац ниже в сообщение.

> Выполни сессию 14g плана `user/foundation/`: покажи в миниатюре экрана камеры настоящую картинку последнего сохранённого снимка с растворением по замеру iOS. Сначала прочитай `user/foundation/README.md` (решения 96, 138, 150, 154–157), отчёты `user/foundation/results/14.md`, `results/14e.md`, `results/14d.md`, `docs/ios-camera/motion.md` (раздел 4.1, строка «Миниатюра после снимка»), потом этот файл.

## Зачем отдельная подсессия

Решение 157: миниатюра выделена из 14d, когда в 14d вошла вспышка Auto (решение 153). Решение 138: миниатюре нужен новый элемент рисования «картинка», которого в `DrawList` нет.

## Решения владельца (вход)

- **154** — картинка появляется, когда файл СОХРАНЁН («сохранено» пришло последним). Время «нажатие → картинка» замерить на телефоне и сравнить с ≈ 0,30 с iOS. Медленная запись HEIF — бэклог.
- **155** — пиксели — маленькая копия в обычной памяти (≈ 256 px по длинной стороне, ≈ 0,2 МБ). GPU уменьшает снимок, копия уходит в память, экран держит её за нейтральным хэндлом, рисование загружает её в текстуру.
- **156** — до первого снимка миниатюра пустая; превью из галереи при запуске — бэклог.

## Что есть сейчас (разведка 14d, сверить с кодом)

- Виджет `camera-screen/src/widget/thumbnail.rs`: стеклянный круг + серая точка с `TODO(миниатюра)`. Состояние `ThumbnailState::{Empty, Last{shot}}` (`shutter.rs`), «сохранено» ставит `Last` в `reduce/shutter.rs::on_capture_finished`. Пикселей у экрана нет.
- `ui-draw`: `DrawItem::{Shape, Glass, Text, Icon}`, `DrawList: Clone + PartialEq`. Эталон пикселя на CPU есть только у фигур и стекла (`pixel_reference.rs`); паритет иконок — CPU-билинейная выборка в тесте `ui-render-vulkan/tests/text_icons.rs`.
- `ui-render-vulkan`: конвейеры `shape`, `glyph`, `glass`. Атлас SDF загружается один раз (`SampledTexture::upload` — блокирующая разовая отправка, на кадре нельзя). Привязка ресурсов на слот, старые ресурсы живут до fence слота (образец — `RetiredPyramid`).
- Проявленный снимок — `isp-vulkan::photo::DevelopedPhoto` (`Rgba8StorageImage` `R8G8B8A8_UNORM`, storage + transfer-src, без SAMPLED, полный кадр ≈ 48 МБ). Уменьшения нигде нет. Картинка живёт от `DevelopProgress::Done` до показа в кодер или readback (`engine_steps.rs::deliver_developed`).
- Наружу из рендера — `DevelopEvent` (`still-contract/src/develop.rs`); фазы экрану — `StillScreenLedger` (`fasticamera-app/src/still_screen_ledger.rs`) через `ScreenAction::CaptureFinished` (без пикселей).

## Ловушки (найдены до сессии)

1. **Протокол «ровно один итог».** Превью — не итог снимка: отдельное событие, `Failed` его выбрасывает. Не трогать правило `NotSecured / PrimaryRendered / PrimaryReadback / Failed`.
2. **Цвет.** Снимок — sRGB 8 бит, экран — Display P3 (swapchain). У элемента «картинка» — явная кодировка источника, перевод в цвет экрана — по правилу `ui-draw` (закодированные значения экрана). Решить до тестов паритета.
3. **Геометрия.** Поворот и кадрирование — из `StillFrameFacts` (кадрирование уже в проявленной картинке? проверить). Миниатюра iOS — круг с заполнением («cover»).
4. **Загрузка без блокировки.** Новая картинка — копия в текстуру записью в командный буфер кадра (staging), не `SampledTexture::upload`. Старая текстура живёт, пока слоты в полёте.
5. **Растворение двух картинок** — два элемента подряд (старая `1 − t`, новая `t`) или один элемент с двумя текстурами. Длительность 0,13–0,17 с `[measured]`, время — из `ctx.now` экрана.
6. **Размеры модулей.** `engine_steps.rs` (≈ 650) и `vulkan_gpu.rs` (≈ 670) у предела — уменьшение снимка в отдельном модуле. Все `match` по `DrawItem` (`items.rs`, `bounds.rs`, `validate.rs`, `plan.rs` в двух местах, тестовые стенды) обновить вместе.
7. **Жизнь без экрана (14e).** «Сохранено» может прийти, пока экрана нет: копия в памяти доживает до возврата, экран применяет её при `apply_pending_input`.

## Архитектура (предложение, сверить с кодом)

- `ui-draw`: `DrawItem::Image(ImageItem{image: UiImageRef, transform, size_px, fit, corner/круг, opacity})`; `UiImageRef` — нейтральный хэндл (`Arc` пикселей + номер версии, `PartialEq` по номеру), кодировка источника явная; CPU-эталон `shade_image_pixel`.
- `ui-render-vulkan`: конвейер `image`, кэш текстур по номеру версии, загрузка в командный буфер кадра, учёт в счётчиках и лимитах.
- Движок снимков: уменьшение проявленной картинки на GPU (отдельный модуль), readback ≈ 0,2 МБ по доказательству своей работы (`seal`), событие превью рядом с итогом.
- Приложение: превью хранится у учёта снимков до «сохранено», уходит в экран отдельным каналом (не в `ScreenAction`); `Failed` его выбрасывает.
- Экран: `ThumbnailState::Last{shot, picture}` + предыдущая картинка и момент смены для растворения.

## Тесты

- Паритет CPU-эталона и GPU для элемента «картинка» (с допуском), golden миниатюры.
- Растворение по времени: доля новой картинки в начале, середине и конце 0,13–0,17 с.
- Картинка того снимка, чьё «сохранено» пришло последним (два снимка, итоги в обратном порядке); `Failed` картинку не ставит.
- Сквозной ПК-тест: нажатие → проявление → «сохранено» → в `DrawList` экрана элемент «картинка» с пикселями этого снимка.
- Сворачивание посреди записи → после возврата миниатюра показывает снимок.
- Телефон: время «нажатие → картинка», взгляд владельца.

## Критерий выхода

- Миниатюра показывает последний сохранённый снимок с растворением по замеру, переживает сворачивание.
