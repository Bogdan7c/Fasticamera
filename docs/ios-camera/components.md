# Переиспользуемые элементы: каталог `ui-kit`

Часть спецификации экрана камеры (сессия 09). Требование владельца (решение 84): **никакого дублирования** — элементы экрана архитектурно переиспользуемы. Каждый виджет экрана камеры собирается из общих «кирпичей», а не пишется заново. Владелец выбрал отдельный crate `ui-kit`.

Разбор спецификации (`layout.md`, `behavior.md`, `motion.md`) показал: на экране около двадцати элементов, но различных механик всего около десяти. Колесо зума, панель экспозиции и колёса ручного режима — одна и та же шкала с упорами. Карусель режимов — та же физика прокрутки. Меню Controls, карточка инструмента и панель экспозиции — одно и то же стекло: шторка появляется на месте, карточка растёт из шторки или появляется на месте (уточнено в 12a).

## 1. Слои

| Слой | Crate | Что в нём | Чего в нём нет |
|---|---|---|---|
| Механика | `ui-core` (10) | дерево, вёрстка, жесты с арбитражем, скорость, пружины, **один движок «прокрутка → проекция броска → прилипание к упору → резинка»**, часы анимаций | готовых элементов, внешнего вида |
| Элементы | **`ui-kit`** (новый, решение 84) | элементы K1–K10 ниже: состояние, жесты, раскладка, описание вида; модели значений; токены | знаний о камере (шкала не знает, что она «зум»), GPU, Android |
| Рисование | `ui-render-vulkan` (11) | SDF-фигуры, текст, иконки из атласа, материал стекла `GlassStyle` | логики элементов |
| Экран | `camera-screen` (12–15) | **сборка** виджетов из элементов `ui-kit` и привязка к состоянию камеры (`ScreenState`) | своих жестов, физики и рисования там, где их даёт `ui-kit` |

Зависимости (guardrail `scripts/crate-boundaries.toml`): `ui-kit` → `ui-core` и `shell-contract` (хаптика); `ui-kit` не зависит от `camera-*`, `gpu-*`, `android-*`, `render-loop`. `camera-screen` → `ui-kit` + `ui-core`.

### Модели значений (общие для K3, K5, K6)

| Модель | Что задаёт | Кто пользуется |
|---|---|---|
| Квантованная линейная | диапазон, шаг, «ноль» | EV ±2 с шагом 1/3 — **одна модель** для панели Exposure и «солнца» |
| Логарифмическая | диапазон, опорные точки | зум (0,5…2×, упоры на `.5`, `1×`, `2`), фокус |
| Ряд значений | список допустимых значений | выдержка (1/8000 … 1 с), ISO по 1/3 ступени, таймер |
| Кельвины + оттенок | две оси | баланс белого (15) |

Пределы модели приходят снаружи (из возможностей текущей камеры), модель их не знает.

### Токены — одно место для каждого числа

| Токены | Источник | Правило |
|---|---|---|
| Раскладка (размеры, отступы, положения в pt) | `layout.md` | ни одного числа в pt прямо в виджете |
| Движение (именованные пружины: `smooth`, `snappy`, `camera.snap`, `camera.sheet` и т.д.) | `motion.md` | виджет ссылается на имя, а не на `response`/`duration` |
| Типографика (кегли, трекинг) | `assets.md` | — |
| Иконки | один атлас (`assets.md`, решение 81) | `IconId`, а не файл |
| Хаптика (событие → паттерн) | `haptics.md` | одна таблица, виджет сообщает событие |
| Стекло | пресеты `GlassStyle` (`glass.md` раздел 6) | — |

## 3. Правила

1. Виджет экрана камеры — это **сборка** элементов `ui-kit` и привязка к состоянию. Если нужного поведения нет в `ui-kit`, оно добавляется туда (параметром или новым элементом), а не пишется в `camera-screen`.
2. Элемент `ui-kit` не знает предметной области: `SnapScale`, а не `ZoomWheel`; смысл значений — в модели значений и привязке.
3. **Правило второго использования**: если вторая сессия пишет похожий код (жест, физику, отрисовку, модель значения), она выносит его в `ui-kit`. Ревью каждой UI-сессии отдельно проверяет дублирование.
4. Числа — только в токенах. Литерал размера, длительности или пружины внутри виджета — ошибка ревью.
5. Тесты: элемент `ui-kit` проверяется один раз полностью (жесты, прилипание, граничные значения, хаптика по событиям) на ПК; виджет экрана — проверкой своей конфигурации и привязки, без повторения тестов механики.
